# Продвинутые запросы и Манипуляция данными

> [!abstract] Суть
> Продвинутый SQL включает инструменты для структурирования сложных запросов (CTE), работы с иерархиями (рекурсия) и эффективного управления жизненным циклом данных (DELETE vs TRUNCATE).

## Простыми словами

*   **CTE** — это создание «временной таблицы» прямо внутри запроса, чтобы не писать огромные вложенные подзапросы. Это как сохранить промежуточный результат в переменную, чтобы код читался как рассказ: «Сначала возьмем это (CTE), а потом объединим с тем».
*   **Рекурсия** — это когда запрос вызывает сам себя. Нужно, когда данные вложены друг в друга (например, начальник -> подчиненный -> его подчиненный).
*   **DELETE vs TRUNCATE** — это как стирать ластиком по одной строчке (DELETE) против того, чтобы просто выкинуть весь лист и положить новый (TRUNCATE).

## Ответ

**Формальные определения (из файла вопросов)**

1.  **Обобщенные табличные выражения (CTE)**
    Определяются ключевым словом `WITH`. Позволяют создать именованный временный набор данных, который существует только во время выполнения одного запроса.
    *   *Зачем*: Улучшают читаемость кода, позволяют переиспользовать один и тот же подзапрос несколько раз в одном SELECT.

2.  **Рекурсивные CTE**
    Это CTE, которое ссылается на само себя. Состоит из двух частей:
    *   **Anchor (якорь)** — базовый запрос (например, корень дерева).
    *   **Recursive member** — запрос, который соединяется с самим CTE. Используется для обхода деревьев, графов и генерации последовательностей.

3.  **DELETE vs TRUNCATE**

| Критерий | DELETE | TRUNCATE |
| :--- | :--- | :--- |
| **Тип команды** | DML (Манипуляция данными) | DDL (Определение данных) |
| **Условие WHERE** | Можно удалять конкретные строки | Нельзя, удаляет всё |
| **Производительность** | Медленно (удаляет построчно) | Очень быстро (освобождает блоки памяти) |
| **Логирование** | Каждая строка фиксируется в логе | Минимальное логирование |
| **Сброс IDENTITY** | Не сбрасывает счетчик ID | Сбрасывает ID в начальное значение |

4.  **Оператор LIKE**
    Используется для поиска по маске. Основные символы:
    *   `%` — любая последовательность символов (включая пустую).
    *   `_` — ровно один любой символ.

5.  **PIVOT-таблицы**
    Это разворот строк в колонки. Например, если у вас есть продажи по месяцам в столбик, PIVOT позволяет сделать названия месяцев заголовками колонок. В разных СУБД реализуется либо через функцию `PIVOT`, либо через `CASE WHEN` с агрегацией.

## Короткий пример

Использование CTE и LIKE:
```sql
WITH HighSales AS (
    SELECT product_name, amount
    FROM sales
    WHERE product_name LIKE 'Pro%' -- Начинается на Pro
)
SELECT * FROM HighSales WHERE amount > 1000;
```

## Типичные ошибки

*   **Бесконечная рекурсия**: Если в рекурсивном CTE нет условия выхода, запрос будет выполняться, пока не упадет по тайм-ауту или лимиту итераций.
*   **TRUNCATE и Foreign Keys**: Нельзя сделать TRUNCATE таблицы, на которую ссылаются другие таблицы через внешний ключ (даже если они пустые) — СУБД выдаст ошибку.

## Каверзные вопросы

> [!question] Сработают ли триггеры при выполнении TRUNCATE?
> Нет. Команда TRUNCATE не «видит» отдельные строки, поэтому триггеры на удаление (ON DELETE) не запускаются.

> [!question] Можно ли откатить (ROLLBACK) команду TRUNCATE?
> В большинстве современных СУБД (PostgreSQL, SQL Server), если TRUNCATE был внутри транзакции, его можно откатить. Однако в MySQL это вызывает неявный коммит, и откат невозможен.

## Проверка себя

*   Чем `%` отличается от `_` в операторе LIKE?
*   Когда CTE лучше обычного подзапроса?
*   Какую команду вы выберете для очистки логов за 5 лет, если нужно оставить данные за последний месяц: DELETE или TRUNCATE? (Ответ: DELETE, так как нужно условие WHERE).
