# Оконные функции и Агрегация

> [!abstract] Суть
> Оконные функции выполняют вычисления над набором строк, которые связаны с текущей строкой, но, в отличие от обычной агрегации, они не схлопывают результат в одну строку, а сохраняют все детали исходного запроса.

## Простыми словами

Представьте школьный класс.
*   **Обычная агрегация (GROUP BY)** — это когда вы просите всех учеников выйти из класса, а на двери вешаете бумажку: «Средний рост в этом классе — 160 см». Самих учеников вы больше не видите.
*   **Оконная функция** — это когда вы заходите в класс и каждому ученику на парту кладете записку: «Твой рост 170 см, а средний по классу — 160 см». Вы видите и конкретного человека, и результат вычисления по группе (окну).

## Ответ

**Формальное определение и синтаксис**

Оконная функция определяется конструкцией `OVER()`. Синтаксис: 
`ФУНКЦИЯ(аргумент) OVER (PARTITION BY колонка_группировки ORDER BY колонка_сортировки)`

*   **PARTITION BY** — аналог GROUP BY, определяет границы «окна».
*   **ORDER BY** — определяет порядок строк внутри окна (критично для функций ранжирования и накопления).

**Сравнение: Агрегация vs Оконные функции**

| Критерий | Агрегация (GROUP BY) | Оконные функции |
| :--- | :--- | :--- |
| **Количество строк** | Уменьшается (схлопывается до групп) | Сохраняется (сколько вошло, столько и вышло) |
| **Детализация** | Теряем индивидуальные данные строк | Видим данные строки рядом с агрегатом |
| **Фильтрация** | Используется HAVING для групп | Фильтруются через подзапросы/CTE (нельзя в WHERE) |

**Функции ранжирования (из файла вопросов)**

Если у нас есть набор строк, где значения для ранжирования повторяются (дубли), функции ведут себя по-разному:

Пример данных: Продажи — 100, 100, 80, 50.
*   **ROW_NUMBER()**: Просто нумерует строки подряд. Даже для одинаковых продаж даст разные номера. 
    *   *Результат: 1, 2, 3, 4.*
*   **RANK()**: Присваивает одинаковый ранг дублям, но пропускает следующие значения. 
    *   *Результат: 1, 1, 3, 4 (номер 2 пропущен).*
*   **DENSE_RANK()**: Присваивает одинаковый ранг дублям, но не пропускает номера. 
    *   *Результат: 1, 1, 2, 3.*

## Решение прикладных задач

**Задача: Добавить численный индекс в SELECT для списка товаров**
Если в таблице есть только имена товаров, индекс можно сгенерировать на лету:
```sql
SELECT 
    ROW_NUMBER() OVER(ORDER BY product_name) as numerical_index,
    product_name
FROM products;
```

## Типичные ошибки

*   **Попытка использовать в WHERE**: Нельзя написать `WHERE ROW_NUMBER() = 1`. Оконные функции вычисляются в самом конце, после фильтрации строк. Чтобы отфильтровать по окну, нужно использовать CTE или подзапрос.
*   **Путаница с HAVING**: HAVING работает только с группами из GROUP BY. Оконные функции к HAVING отношения не имеют.

## Каверзные вопросы

> [!question] В какой последовательности выполняются части запроса: JOIN, WHERE, GROUP BY и Оконные функции?
> Оконные функции выполняются после JOIN, WHERE, GROUP BY и HAVING, но перед DISTINCT и итоговым ORDER BY. Поэтому они видят уже отфильтрованный и сгруппированный набор данных.

> [!question] Можно ли использовать агрегатные функции (SUM, AVG) как оконные?
> Да, любая агрегатная функция становится оконной, если добавить к ней `OVER()`. Например, `SUM(salary) OVER(PARTITION BY department)` посчитает сумму зарплат по отделу для каждой строки сотрудника.
