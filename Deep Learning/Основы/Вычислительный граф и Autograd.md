# Вычислительный граф и Autograd

> [!abstract] Суть
> Вычислительный граф — это представление функции в виде узлов-операций и рёбер-тензоров. Autograd — механизм, который автоматически вычисляет градиенты, обходя этот граф в обратном направлении.

## Ответ

**Концепция вычислительного графа**
Любую нейросеть можно разложить на элементарные операции (сложение, умножение, ReLU). Переменные (веса, входы) — это листья графа, операции — узлы. Граф позволяет свести дифференцирование к последовательному применению правила цепочки (chain rule).

**Механизм Autograd**
Современные фреймворки (PyTorch, TensorFlow) избавляют от ручного вывода производных.
1. **Динамическое построение:** Во время прямого прохода (`forward`) Autograd запоминает последовательность операций и кэширует промежуточные результаты.
2. **Автоматический Backward:** При вызове `.backward()` система обходит граф от функции потерь к входам, перемножая локальные производные на глобальные градиенты.

## Формула / Схема

Схема для $f(x, y) = (x + y) \cdot y$:
$$x, y \to [+] \to q \to [\times y] \to f$$

## Короткий пример

Реализация на PyTorch:
```python
import torch

x = torch.tensor(2.0, requires_grad=True)
y = torch.tensor(3.0, requires_grad=True)

f = (x + y) * y # f = 15.0
f.backward()

print(x.grad) # 3.0
print(y.grad) # 8.0
```

## Типичные ошибки

- **Забыть `torch.no_grad()` на инференсе:** Без этого фреймворк будет строить граф и копить градиенты на валидации, что быстро забьет оперативную память (OOM).
- **requires_grad=False:** Пытаться обучать тензор, у которого не выставлен флаг отслеживания градиентов.

## Каверзные вопросы

> [!question] Обязательно ли вручную прописывать производные для нового слоя?
> Нет, если слой собран из стандартных операций фреймворка (сложение, `torch.matmul` и т.д.), Autograd сам разберется, как его дифференцировать.
