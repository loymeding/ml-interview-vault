# Метод обратного распространения ошибки (Backpropagation)

> [!abstract] Суть
> Backpropagation — это эффективный алгоритм вычисления градиентов функции потерь по всем параметрам сети за один проход от конца к началу. Он базируется на правиле дифференцирования сложной функции (Chain Rule) и концепции вычислительного графа. Главный секрет эффективности: во время прямого прохода (Forward Pass) сеть уже вычисляет и кэширует все необходимые числа для расчёта локальных производных, превращая обратный проход в простую серию умножений матриц.

## Ответ

### 1. Проблема вычисления градиентов

Для обучения сети методом градиентного спуска нам нужно вычислить $\frac{\partial L}{\partial W}$ для каждой матрицы весов $W$. Если бы мы считали градиент по каждому параметру отдельно (через приращения или прямое дифференцирование с начала), это потребовало бы колоссального количества вычислений для миллионов весов.

### 2. Вычислительный граф и Chain Rule

Нейросеть можно представить как **вычислительный граф**, где узлы — это математические операции, а рёбра — тензоры, текущие между ними. В основе алгоритма лежит правило дифференцирования сложной функции (Chain Rule): если $y = f(g(x))$, то:

$$\Large \frac{dy}{dx} = \frac{df}{dg} \cdot \frac{dg}{dx}$$

В терминах графа для любого узла мы можем определить:
- **Локальный градиент:** производная выхода узла по его входу
- **Глобальный (upstream) градиент:** градиент итоговой функции потерь $L$ по выходу текущего узла

Чтобы получить итоговый градиент по входу, нужно просто **умножить** пришедший сверху глобальный градиент на локальный.

### 3. Две фазы алгоритма

**Forward Pass (Прямой проход):** мы подаём данные на вход сети, вычисляем выходы слой за слоем вплоть до функции потерь $L$. **Критически важно:** на этом этапе мы сохраняем в памяти (кэшируем) все промежуточные активации, так как они нужны для расчёта локальных градиентов.

**Backward Pass (Обратный проход):** мы стартуем от функции потерь ($\frac{\partial L}{\partial L} = 1$) и идём в обратном направлении. На каждом узле мы берём пришедший глобальный градиент, умножаем его на локальный и передаём дальше «вниз».

### 4. Матричные производные

В реальных сетях по графу текут не числа, а многомерные тензоры (батчи данных). Благодаря алгебре всё сводится к элегантному матричному перемножению. Например, если $Z = XW$, то:

$$\Large \frac{\partial L}{\partial X} = \frac{\partial L}{\partial Z} W^T, \qquad \frac{\partial L}{\partial W} = X^T \frac{\partial L}{\partial Z}$$

где:
- $X$ — входной тензор (батч данных)
- $W$ — матрица весов
- $Z = XW$ — выход линейного слоя
- $\frac{\partial L}{\partial Z}$ — градиент, «пришедший» от следующего слоя

## Формула / Схема

Рассмотрим простой вычислительный граф: $f(x, y, z) = (x + y) \cdot z$. Введём $q = x + y$. Тогда $f = q \cdot z$.

Пусть $x = -2,\; y = 5,\; z = -4$.

**Forward:** $q = -2 + 5 = 3$. $f = 3 \cdot (-4) = -12$.

**Backward:**
- $\frac{\partial f}{\partial f} = 1$
- $\frac{\partial f}{\partial z} = q = 3$. Глобальный градиент для $z$: $1 \cdot 3 = 3$
- $\frac{\partial f}{\partial q} = z = -4$. Глобальный градиент для $q$: $1 \cdot (-4) = -4$
- Узел суммы: $\frac{\partial q}{\partial x} = 1$, $\frac{\partial q}{\partial y} = 1$. Глобальный градиент для $x$ и $y$: $-4$

## Короткий пример

В PyTorch весь механизм вычислительных графов и backprop инкапсулирован в модуль `autograd`:

```python
# 1. Forward pass (PyTorch автоматически строит граф и сохраняет активации)
outputs = model(inputs)
loss = criterion(outputs, labels)

# 2. Обязательно обнуляем градиенты с прошлого шага!
optimizer.zero_grad()

# 3. Backward pass (вычисляет dL/dW для каждого тензора с requires_grad=True)
loss.backward()

# 4. Обновление весов
optimizer.step()
```

## Типичные ошибки

- **Забыть `optimizer.zero_grad()`:** по умолчанию PyTorch **аккумулирует** (суммирует) градиенты при каждом вызове `.backward()`. Если их не обнулять, новый градиент прибавится к прошлому, и веса улетят в космос.
- **Не использовать `torch.no_grad()` на этапе инференса:** без этого PyTorch продолжит кэшировать все промежуточные активации для обратного прохода, что приведёт к колоссальной утечке видеопамяти GPU.
- **«Отрыв» тензора от графа:** если вы хотите сохранить значение функции потерь для статистики (например, `losses.append(loss)`), нужно обязательно вызывать `loss.item()`. Если добавить сам тензор `loss`, вы сохраните весь привязанный к нему вычислительный граф, и память быстро закончится.

## Каверзные вопросы

> [!question] Почему для обучения нейронной сети требуется в несколько раз больше видеопамяти (VRAM), чем для её применения (инференса)?
> При инференсе мы можем сразу удалять из памяти активации предыдущего слоя. Но при обучении во время Forward Pass мы **обязаны** сохранить все промежуточные матрицы (активации) каждого слоя, так как они понадобятся для вычисления локальных градиентов во время Backward Pass. Плюс мы должны хранить сами градиенты и параметры оптимизатора (например, моменты в Adam).

> [!question] Как Backpropagation связан с проблемой «затухающих градиентов» (Vanishing Gradients)?
> Из правила Chain Rule следует, что итоговый градиент по весам первых слоёв — это **произведение** множества локальных градиентов слоёв, стоящих выше. Если в сети используется функция активации, производная которой меньше единицы (у Сигмоиды максимум производной равен $0.25$), то при обратном проходе мы многократно умножаем на числа $< 1$. Градиент экспоненциально стремится к нулю, и первые слои перестают обучаться.
