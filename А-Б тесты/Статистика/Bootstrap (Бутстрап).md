# Bootstrap (Бутстрап)

> [!abstract] Суть
> **Bootstrap** — это метод оценки неопределенности статистики через многократное сэмплирование исходных данных **с возвращением**. Он помогает получить стандартную ошибку, доверительный интервал или оценку p-value, когда аналитическая формула дисперсии сложная, ненадежная или вообще неизвестна.

## Ответ

### 1. Интуиция
В реальности у нас есть неизвестная генеральная совокупность и одна наблюдаемая выборка. Bootstrap делает практичное приближение: считает наблюдаемую выборку маленькой моделью генеральной совокупности.

Из этой выборки много раз набираются новые выборки того же размера, но **с возвращением**. Поэтому один объект может попасть в bootstrap-выборку несколько раз, а другой — ни разу. На каждой такой выборке заново считается интересующая статистика: среднее, медиана, конверсия, разница средних, глобальный CTR, ARPU, квантиль и т.д.

Получив много значений статистики, мы строим эмпирическое распределение этой статистики и смотрим, насколько она "гуляет" из-за случайности данных.

### 2. Базовый алгоритм
Пусть есть выборка:

$$\Large
X = \{x_1, x_2, \ldots, x_n\}
$$

и статистика:

$$\Large
T = s(X)
$$

Например, $s(X)$ может быть средним, медианой, конверсией или отношением суммы кликов к сумме показов.

Алгоритм:

1. Взять исходную выборку размера $n$.
2. Сгенерировать bootstrap-выборку $X_b^*$ размера $n$, выбирая объекты из $X$ случайно **с возвращением**.
3. Посчитать статистику $T_b^* = s(X_b^*)$.
4. Повторить шаги 2-3 много раз: $B = 1000$, $5000$, $10000$.
5. Использовать распределение $\{T_1^*, T_2^*, \ldots, T_B^*\}$ для оценки разброса статистики.

### 3. Что можно оценивать через Bootstrap
Bootstrap особенно полезен, когда метрика сложная или ее дисперсию неудобно выводить руками:

- **Среднее**: средний чек, средняя выручка на пользователя.
- **Медиана и квантили**: время доставки, latency, распределения с тяжелыми хвостами.
- **Доли и конверсии**: conversion rate, retention rate.
- **Разность метрик**: $mean(test) - mean(control)$.
- **Относительный uplift**: $\frac{mean(test)}{mean(control)} - 1$.
- **Ratio-метрики**: глобальный CTR, revenue per impression, clicks per session.

Для A/B-тестов важная мысль: bootstrap обычно делают не отдельно для каждой метрики в вакууме, а для **разницы между группами**. Нас интересует распределение эффекта:

$$\Large
\Delta^* = T_{test}^* - T_{control}^*
$$

### 4. Bootstrap в A/B-тестах
Для A/B-теста схема такая:

1. В контрольной группе сэмплировать пользователей с возвращением.
2. В тестовой группе сэмплировать пользователей с возвращением.
3. На каждой паре bootstrap-выборок посчитать метрику в control и test.
4. Посчитать эффект: абсолютный или относительный.
5. По распределению эффектов построить доверительный интервал.

Если 95% доверительный интервал для абсолютного эффекта не содержит 0, это обычно трактуют как статистически значимое отличие на уровне около 5%.

Важно сэмплировать на уровне **единицы рандомизации**. Если эксперимент рандомизировал пользователей, нужно сэмплировать пользователей, а не отдельные события, показы или клики. Иначе зависимость внутри пользователя ломается, и неопределенность будет занижена.

### 5. Почему с возвращением
Если сэмплировать без возвращения выборку того же размера, мы каждый раз будем получать почти исходные данные. Такой процесс плохо имитирует вариативность возможных выборок.

Сэмплирование с возвращением создает естественные флуктуации: одни наблюдения повторяются, другие пропадают. Это дает приближение к тому, как могла бы меняться статистика, если бы мы заново собирали похожие выборки из той же популяции.

### 6. Ограничения
Bootstrap не превращает плохой эксперимент в хороший:

- если рандомизация сломана, bootstrap не исправит смещение;
- если выборка очень маленькая, эмпирическое распределение бедное и интервалы могут быть нестабильны;
- если есть сильная зависимость во времени, нужен не обычный, а блочный bootstrap;
- если данные грязные или есть leakage между группами, метод честно размножит эту проблему;
- для очень больших данных метод может быть дорогим по CPU и памяти.

## Формула / Схема

### Стандартная ошибка
После $B$ bootstrap-итераций стандартную ошибку статистики можно оценить так:

$$\Large
\hat{SE}_{boot} =
\sqrt{
\frac{1}{B - 1}
\sum_{b=1}^{B}
(T_b^* - \bar{T}^*)^2
}
$$

где:

- $T_b^*$ — значение статистики на $b$-й bootstrap-выборке;
- $\bar{T}^*$ — среднее значение bootstrap-статистик;
- $B$ — число bootstrap-итераций.

### Percentile confidence interval
Самый простой доверительный интервал берется по квантилям bootstrap-распределения:

$$\Large
CI_{1-\alpha} =
\left[
q_{\alpha / 2}(T^*),
q_{1 - \alpha / 2}(T^*)
\right]
$$

Для 95% доверительного интервала:

$$\Large
CI_{95\%} =
\left[
q_{0.025}(T^*),
q_{0.975}(T^*)
\right]
$$

### Bootstrap p-value для A/B
Для распределения bootstrap-эффектов $\Delta^*$ можно грубо оценить двусторонний p-value:

$$\Large
p \approx 2 \cdot \min
\left(
P(\Delta^* \le 0),
P(\Delta^* \ge 0)
\right)
$$

На практике чаще смотрят на доверительный интервал эффекта и его бизнес-значимость.

## Короткий пример

### Пример 1. Разница конверсий

```python
import numpy as np

rng = np.random.default_rng(42)

control = np.array([0, 1, 0, 0, 1, 0, 0, 1, 0, 0])
test = np.array([1, 1, 0, 1, 1, 0, 1, 1, 0, 1])

B = 10_000
deltas = []

for _ in range(B):
    control_sample = rng.choice(control, size=len(control), replace=True)
    test_sample = rng.choice(test, size=len(test), replace=True)
    deltas.append(test_sample.mean() - control_sample.mean())

deltas = np.array(deltas)

ci = np.quantile(deltas, [0.025, 0.975])
p_value = 2 * min(np.mean(deltas <= 0), np.mean(deltas >= 0))

print("effect:", test.mean() - control.mean())
print("95% CI:", ci)
print("p-value:", p_value)
```

Если интервал лежит целиком выше 0, тестовая группа дала положительный эффект. Если интервал пересекает 0, данных недостаточно, чтобы уверенно отделить эффект от случайного шума.

### Пример 2. Глобальный CTR

Глобальный CTR:

$$\Large
CTR_{global} = \frac{\sum clicks}{\sum impressions}
$$

Для такой ratio-метрики нельзя просто взять дисперсию пользовательских CTR бездумно: пользователи имеют разное число показов, а отношение сумм ведет себя не так, как среднее индивидуальных отношений.

```python
import numpy as np

rng = np.random.default_rng(42)

control_clicks = np.array([1, 0, 3, 0, 2])
control_impressions = np.array([10, 8, 20, 4, 15])

test_clicks = np.array([2, 1, 4, 0, 3])
test_impressions = np.array([11, 9, 18, 5, 14])

def global_ctr(clicks, impressions):
    return clicks.sum() / impressions.sum()

B = 10_000
deltas = []

for _ in range(B):
    c_idx = rng.choice(len(control_clicks), size=len(control_clicks), replace=True)
    t_idx = rng.choice(len(test_clicks), size=len(test_clicks), replace=True)

    control_ctr = global_ctr(control_clicks[c_idx], control_impressions[c_idx])
    test_ctr = global_ctr(test_clicks[t_idx], test_impressions[t_idx])
    deltas.append(test_ctr - control_ctr)

ci = np.quantile(deltas, [0.025, 0.975])
print("95% CI for CTR delta:", ci)
```

Здесь сэмплируются пользователи целиком: вместе с их кликами и показами. Это сохраняет связь между числителем и знаменателем.

## Типичные ошибки

- **Сэмплировать события вместо пользователей.** Если рандомизация была по пользователям, bootstrap должен переиспользовать пользователей целиком.
- **Сэмплировать без возвращения.** Тогда почти не возникает имитации выборочной вариативности.
- **Сравнивать интервалы групп вместо интервала эффекта.** В A/B-тесте лучше строить распределение $\Delta^*$, а не только отдельные интервалы control и test.
- **Делать слишком мало итераций.** Для черновой оценки может хватить 1000, но для стабильных квантилей часто берут 5000-10000+.
- **Забывать про бизнес-значимость.** Статистически значимый эффект может быть слишком маленьким для продукта.
- **Использовать обычный bootstrap для зависимых данных.** Для временных рядов, сессий с автокорреляцией и кластеров нужны специальные варианты.
- **Считать bootstrap непараметрической магией.** Он не исправляет selection bias, leakage, ошибки логирования и нарушение дизайна эксперимента.

## Каверзные вопросы

> [!question] Bootstrap всегда лучше t-теста?
> Нет. Если метрика простая, выборка большая, условия классического теста выполняются, t-тест быстрее, проще и хорошо интерпретируется. Bootstrap полезнее там, где аналитическая дисперсия сложная или распределение сильно неудобное.

> [!question] Почему bootstrap можно применять к медиане?
> Потому что метод не требует гладкой аналитической формулы для статистики. Мы просто пересчитываем медиану на тысячах переcэмплированных выборок и смотрим на ее эмпирический разброс.

> [!question] Что важнее: число bootstrap-итераций или размер исходной выборки?
> Число итераций уменьшает шум самой процедуры, но не добавляет новой информации. Если исходная выборка маленькая или смещенная, 100000 итераций не сделают вывод надежным.

> [!question] Можно ли bootstrap-ить относительный uplift?
> Да. На каждой итерации нужно считать $\frac{T_{test}^*}{T_{control}^*} - 1$, а затем строить интервал уже для этого uplift. Но нужно следить, чтобы знаменатель не был близок к нулю.
