# ETA в Яндекс Картах — baseline, backtesting и расчёт маршрута

> [!abstract] Главная мысль
> Для ETA (Estimated Time of Arrival — прогноз времени прибытия) нужно сначала определить маршрут и уровень предсказания: время для участка дороги или полный путь от точки A до B. Хороший V1 может быть статистическим baseline по истории скоростей. Затем важно честно проверить будущее по прошлым данным и только после этого усложнять модель.

## 1. Уточнение задачи

Пользователь задаёт начало и конец пути и ожидает ETA. Нужно уточнить тип транспорта, плановый или текущий трафик, допустимую задержку ответа, горизонт прогноза и требование к обновлению во время поездки. На карте маршрут состоит из дорожных сегментов; каждый сегмент имеет длину, историческую и текущую скорость.

## 2. Простая модель V1

Для каждого сегмента храним статистику скорости по временным интервалам, дню недели и сезону. ETA сегмента = длина / ожидаемая скорость. Для полного маршрута суммируем ETA сегментов выбранного кратчайшего пути. Взвешенное среднее по похожим историческим поездкам — хороший baseline: он дешёвый, объяснимый и задаёт нижнюю планку для ML.

Данные очищаем от нулевых и невозможных скоростей, GPS-скачков, отменённых поездок и неверных временных меток. Выделяем отдельные таблицы для обучения и проверки, чтобы онлайн-запрос не использовал информацию из будущего.

## 3. Backtesting и метрики

Для временной задачи делаем разбиение по месяцам или последовательным периодам. Модель обучается на записях до даты T, затем выдаёт ETA для поездок после T. Так проверяется сценарий настоящего продакшена. Случайное перемешивание нарушило бы причинный порядок и дало бы утечку.

Основная метрика — ошибка между прогнозом и фактическим временем: MAE в минутах, относительная ошибка и перцентили. Бизнесу может быть важнее p90 ошибки: редкое сильное опоздание портит доверие сильнее, чем средняя ошибка. Считаем метрики по городам, времени суток, длине маршрута, пробкам и типам дорог.

## 4. Архитектура сервиса

Бэкенд состоит из двух частей: функция ETA назначает время каждому близкому дорожному сегменту, а модуль маршрутизации выбирает лучший путь и суммирует времена. Для низкой задержки сегментные прогнозы можно кэшировать и обновлять пакетно; для текущего трафика добавлять короткий онлайн-слой.

Мониторим задержку ответа, долю пропущенных сегментов, распределение скорости, дрейф и ошибки по задержанным фактическим поездкам. Если модель не уверена или данных мало, используем baseline и показываем безопасную оценку, а не экстремальное число.
