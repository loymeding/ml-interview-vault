# Языковое моделирование и алгоритмы генерации текста

> [!abstract] Суть
> Языковое моделирование (Language Modeling, LM) — это задача предсказания следующего слова (токена) на основе истории предыдущих слов. В основе любого современного чат-бота — та же математика. Качество оценивается **Перплексией** (Perplexity): чем ниже, тем лучше. Для извлечения текста из обученной модели применяются алгоритмы декодирования — детерминированные (**Beam Search**) для точных задач вроде перевода и стохастические (**Top-K / Top-p**) для творческой генерации.

## Ответ

### 1. Постановка задачи

Задача языковой модели — оценить вероятность слова $w_t$ в контексте всей предшествующей истории $w_1, \ldots, w_{t-1}$. Именно это делает T9 в телефоне или ChatGPT.

Обучение: максимизировать совокупную вероятность реальных текстов (= минимизировать кросс-энтропию), чтобы модель «привыкала» к живому языку.

### 2. Классика: N-граммные модели

До нейросетей язык моделировали через частоты совместных вхождений N подряд идущих слов (биграммы, триграммы и т.д.).

Специальные токены:
- `<s>` / `<bos>` — начало предложения
- `<eos>` — конец предложения
- `<unk>` — слово вне словаря

**Проклятие размерности:** большинство 10-словных фраз никогда не встречалось в обучающей выборке → вероятность = 0. Поэтому N-граммы ограничены N ≤ 3–4.

### 3. Оценка качества: Перплексия

Перплексия — степень «удивления» модели от реального текста. Если PP = 10, модель в среднем сомневается между 10 равновероятными вариантами. Идеальная PP → 1.

### 4. Детерминированная генерация

**Жадный поиск (Greedy Search):** на каждом шаге выбирается токен с максимальной вероятностью. Быстро, но легко загоняет себя в смысловой тупик и зацикленные фразы.

**Beam Search (Лучевой поиск):** поддерживает в памяти $K$ самых вероятных гипотез-цепочек. На каждом шаге развивает все $K$ гипотез, отбирает топ-$K$ по совокупному score. Глобально лучший результат по сравнению с жадным поиском.

### 5. Стохастическая генерация

Нам нужен разнообразный текст → сэмплируем из предсказанного распределения.

**Проблема «длинного хвоста»:** словарь содержит сотни тысяч слов; суммарная вероятность «мусорных» слов существенна — без фильтрации модель периодически выдаёт бессмыслицу.

**Top-K сэмплирование:** жёстко оставляем только K (например, 50) самых вероятных токенов, сэмплируем из них. Минус: K — фиксированный размер окна, неудобный при разной уверенности модели.

**Top-p (Nucleus sampling):** сортируем токены по убыванию вероятности и берём наименьшее подмножество, чья суммарная вероятность ≥ p (например, 0.9). Динамический размер окна: если модель уверена — в ядро попадёт 1–2 слова; если сомневается — десятки.

**Temperature:** масштабирует логиты перед Softmax ($T < 1$ — модель консервативнее, $T > 1$ — случайнее).

### 6. Когда что использовать

| Задача | Алгоритм |
|--------|----------|
| Машинный перевод, суммаризация | Beam Search (точность важнее разнообразия) |
| Чат-бот, написание текстов, код | Top-p с Temperature (нужна вариативность) |

### 7. Exposure Bias — ловушка Teacher Forcing

Во время обучения авторегрессионных моделей применяется приём **Teacher Forcing**: на вход следующего шага декодера подаётся *истинный* токен из датасета, а не то, что модель предсказала на предыдущем шаге. Это делает обучение быстрым и стабильным — каждый шаг учится изолированно на идеальном контексте.

Но при **инференсе** учителя нет. Модель вынуждена опираться на **собственные предсказания** как на контекст. Если на шаге 3 допущена ошибка, шаг 4 строится на этой ошибке, шаг 5 — на двух ошибках, и ошибки накапливаются лавинообразно. Это расхождение между режимами обучения и инференса называется **Exposure Bias** («смещение из-за доступа к данным»).

**Практическое следствие:** чем длиннее генерируемая последовательность, тем сильнее накапливается дрейф. Даже очень хорошие языковые модели могут «поплыть» при генерации длинных текстов. Один из частичных ответов на эту проблему — **Scheduled Sampling**: постепенно заменять истинные токены Teacher Forcing на предсказания самой модели в процессе обучения.

## Формула / Схема

**Вероятность последовательности:**
$$\Large P(w_1, \ldots, w_T) = \prod_{t=1}^{T} P(w_t \mid w_1, \ldots, w_{t-1})$$

где:
- $w_t$ — $t$-й токен последовательности
- $w_1, \ldots, w_{t-1}$ — весь предшествующий контекст (история)

**Перплексия (Perplexity):**
$$\Large PP = \exp\!\left(-\frac{1}{T}\sum_{t=1}^{T}\log P(w_t \mid w_{<t})\right) = \exp(H)$$

где:
- $T$ — длина тестовой последовательности (число токенов)
- $P(w_t \mid w_{<t})$ — вероятность, предсказанная моделью для истинного токена
- $H = -\frac{1}{T}\sum \log P(\cdot)$ — кросс-энтропия языковой модели

**Beam Search — score гипотезы (без штрафа за длину):**
$$\Large \text{score}(y_1, \ldots, y_t) = \sum_{\tau=1}^{t} \log P(y_\tau \mid y_{<\tau})$$

где:
- $y_\tau$ — $\tau$-й токен гипотезы
- $K$ лучших гипотез по этому score сохраняются на каждом шаге

**Beam Search с Length Penalty (штраф за длину):**
Обычный Beam Search систематически фаворизирует **короткие** последовательности: каждый новый токен умножает совокупную вероятность на число $\leq 1$, поэтому длинные цепочки автоматически имеют меньший суммарный score. Чтобы сравнивать гипотезы честно, применяется нормировка:

$$\Large \text{score}_{\text{LP}}(y) = \frac{1}{|y|} \sum_{\tau=1}^{|y|} \log P(y_\tau \mid y_{<\tau})$$

где:
- $|y|$ — длина гипотезы в токенах
- $\frac{1}{|y|}$ — нормировка, превращающая суммарный log-prob в среднюю уверенность на токен
- Теперь более длинный, но семантически полный ответ не проигрывает обрезанному из-за математического эффекта

## Короткий пример

```python
from transformers import GPT2LMHeadModel, GPT2Tokenizer

model = GPT2LMHeadModel.from_pretrained("gpt2")
tokenizer = GPT2Tokenizer.from_pretrained("gpt2")

inputs = tokenizer("Once upon a time", return_tensors="pt")

# Beam Search — для точного/структурированного текста
ids_beam = model.generate(**inputs, num_beams=5, max_length=30)

# Top-p sampling — для творческой генерации
ids_topp = model.generate(**inputs, do_sample=True, top_p=0.9, temperature=0.8, max_length=30)
```

## Типичные ошибки

- **Сравнивать Perplexity моделей с разными токенизаторами:** PP зависит от размера словаря. Модель, разбивающая текст на символы, математически даст совсем другую PP, чем модель с целыми словами — сравнивать напрямую нельзя.
- **Использовать Beam Search для open-ended генерации (рассказов, диалогов):** тексты статистически «слишком правильные» и звучат роботизированно. Для творческих задач — Top-p с Temperature.

## Каверзные вопросы

> [!question] Что произойдёт, если при Top-p генерации (p=0.9) самый вероятный следующий токен предсказан с вероятностью 0.95?
> В ядро попадёт ровно один токен, и стохастическая генерация автоматически схлопнется в детерминированный жадный выбор. Это корректное поведение: если модель на 95% уверена в следующем слове, сэмплировать что-то иное нет смысла.
