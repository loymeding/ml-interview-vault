# Decoding и sampling в LLM — Temperature, Top-p, Top-k, Beam Search

> [!abstract] Суть
> Decoding превращает распределение вероятностей следующего токена в конкретный текст. Greedy и beam search выбирают наиболее вероятные продолжения, а temperature, top-k и top-p добавляют управляемую случайность для более естественной открытой генерации.

## Ответ

### 1. Temperature

Температура масштабирует logits перед softmax:

$$\Large p_i = \frac{\exp(z_i/T)}{\sum_j \exp(z_j/T)}$$

где:
- $z_i$ — logit токена $i$;
- $T$ — temperature;
- $p_i$ — вероятность токена после softmax.

При $T \to 0$ распределение становится острым: модель почти всегда выбирает самый вероятный токен. При большом $T$ распределение сглаживается: редкие токены получают больше шансов.

Практически:
- код, математика, factual QA: низкая temperature;
- диалоги и креативные задачи: умеренная;
- слишком высокая temperature ломает связность и фактологию.

### 2. Top-k sampling

Top-k оставляет только $k$ самых вероятных токенов, остальные зануляет, затем нормирует распределение.

Плюсы:
- просто;
- отрезает длинный хвост мусорных токенов;
- удобно как safety-ограничитель.

Минус: $k$ фиксирован. Если модель очень уверена, $k=50$ может быть слишком широким. Если модель не уверена, $k=50$ может быть слишком узким.

### 3. Top-p / nucleus sampling

Top-p выбирает минимальное множество токенов, сумма вероятностей которого не меньше $p$:

$$\Large S_p = \min S: \sum_{i \in S} p_i \ge p$$

где:
- $S_p$ — nucleus, набор допустимых токенов;
- $p$ — порог, например $0.9$ или $0.95$.

Размер ядра адаптивен:
- модель уверена → ядро маленькое;
- распределение размазано → ядро расширяется.

Поэтому top-p часто естественнее top-k для open-ended генерации.

### 4. Beam search

Beam search поддерживает несколько лучших гипотез вместо одной. На каждом шаге:
1. расширяет каждый из $B$ префиксов всеми возможными токенами;
2. считает joint log probability;
3. оставляет $B$ лучших новых префиксов.

Score гипотезы:

$$\Large \text{score}(y_{1:t}) = \sum_{\tau=1}^{t}\log p(y_\tau \mid y_{<\tau}, x)$$

Beam search хорошо подходит для machine translation и summarization, где высокая sequence-level probability часто коррелирует с качеством.

Для чатовых LLM beam search часто даёт слишком осторожный, повторяющийся и шаблонный текст. Поэтому в диалогах обычно используют temperature + top-p/top-k.

### 5. Length penalty

Без нормировки beam search любит короткие последовательности: каждый новый токен добавляет отрицательный log-probability.

Простая нормировка:

$$\Large \text{score}_{\text{norm}}(y) = \frac{1}{|y|^\alpha}\sum_{t=1}^{|y|}\log p(y_t \mid y_{<t}, x)$$

где:
- $|y|$ — длина гипотезы;
- $\alpha$ — сила length penalty;
- $\alpha=0$ — нет нормировки;
- больше $\alpha$ — меньше штраф за длину.

## Формула / Схема

**Порядок применения typical sampling stack:**

```text
logits
-> temperature scaling
-> repetition/frequency penalties
-> top-k/top-p filtering
-> softmax
-> sampling
```

Важно: temperature меняет форму распределения, а top-k/top-p отрезают часть кандидатов.

## Короткий пример

```python
outputs = model.generate(
    **inputs,
    do_sample=True,
    temperature=0.7,
    top_p=0.9,
    top_k=50,
    max_new_tokens=256,
)
```

Для перевода:

```python
outputs = model.generate(
    **inputs,
    num_beams=4,
    length_penalty=0.8,
    do_sample=False,
)
```

## Типичные ошибки

- **Использовать beam search для открытого диалога:** ответы становятся однообразными и слишком безопасными.
- **Поднимать temperature без top-p/top-k:** модель чаще выбирает мусор из длинного хвоста.
- **Сравнивать decoding-стратегии без фиксированного prompt и seed:** стохастика мешает честной оценке.
- **Думать, что top-p и temperature делают одно и то же:** temperature меняет вероятности, top-p ограничивает набор кандидатов.

## Каверзные вопросы

> [!question] Что произойдёт при top-p = 0.9, если самый вероятный токен имеет вероятность 0.95?
> В nucleus попадёт только этот токен, и sampling схлопнется в greedy choice. Это нормально: модель очень уверена.

> [!question] Почему beam search хуже подходит для чата, чем для перевода?
> В переводе есть относительно определённый правильный ответ, и высокая probability часто полезна. В чате много допустимых ответов, а beam search часто выбирает средний, шаблонный и повторяющийся вариант.
