# Transfer Learning в NLP и семейство BERT

> [!abstract] Суть
> Классическое языковое моделирование (GPT) читает текст только слева направо. **BERT** (Bidirectional Encoder Representations from Transformers) использует Энкодер Трансформера и учитывает **двусторонний контекст**. Обучение идёт в два этапа Transfer Learning: сначала предобучение на огромных текстах без разметки через **MLM** (маскирование токенов) и **NSP** (предсказание следующего предложения), затем Fine-Tuning с добавлением линейного слоя под конкретную задачу. Качество стандартизировано оценивается на бенчмарке **GLUE**.

## Ответ

### 1. Пайплайн Transfer Learning и бенчмарк GLUE

Вместо обучения с нуля — два шага:

1. **Предобучение (Self-supervised learning):** берём огромный сырой корпус (весь интернет, Википедия, книги) и заставляем модель выучить структуру языка без ручной разметки.
2. **Fine-tuning:** берём предобученную модель, добавляем сверху линейный слой, обучаем на конкретной задаче (downstream task) с маленьким learning rate.

**GLUE** (General Language Understanding Evaluation) — набор из 9 разнообразных задач (логическое следование, анализ тональности, схожесть предложений и др.) для честной сравнительной оценки понимания языка.

### 2. Задачи предобучения BERT

Классическое предсказание следующего слова не работает для двунаправленного Энкодера — модель могла бы «подглядеть» правильный ответ через Self-Attention. Поэтому BERT учится на двух задачах:

**Masked Language Modeling (MLM):** случайным образом выбирается 15% токенов, модель предсказывает их исходные значения по двустороннему контексту.

**Next Sentence Prediction (NSP):** бинарная классификация — модели подают два предложения, и нужно определить: реально ли второе шло за первым (50% случаев) или выбрано случайно из другого текста.

### 3. Правило 80-10-10 для MLM

Из 15% выбранных токенов:
- **80%** заменяются на `[MASK]` → явная задача восстановления
- **10%** заменяются на случайное слово из словаря → устойчивость к шуму
- **10%** оставляются без изменений → модель не разучивается обрабатывать обычные токены

Почему 10% без изменений? На Fine-tuning никаких `[MASK]` не будет. Чтобы модель формировала качественные эмбеддинги для обычных слов, её заставляют «предсказывать» неизменённые токены.

### 4. Токены `[CLS]` и `[SEP]`

Когда мы подаём в BERT сырой текст, модель получает не просто слова, а служебно размеченную последовательность:

```text
[CLS] это классный фильм [SEP]
```

`[CLS]` ставится **в самое начало** и получает индекс 0. На входном слое это обычный обучаемый эмбеддинг специального токена плюс позиционный эмбеддинг позиции 0. Он ещё не несёт смысла предложения — это заготовка под агрегатор.

Дальше каждый слой Transformer применяет Self-Attention. Все токены смотрят друг на друга, и `[CLS]` тоже может "собирать" информацию из `это`, `классный`, `фильм`. К последнему слою вектор на позиции `[CLS]` становится представлением всей последовательности, поэтому для классификации всего текста берут именно его и подают в линейную голову.

`[SEP]` отмечает конец одиночной последовательности или разделяет пару текстов:

```text
[CLS] sentence A [SEP] sentence B [SEP]
```

Это важно для NSP, entailment, similarity и QA-задач, где BERT должен различать границы сегментов.

### 5. RoBERTa (Robustly Optimized BERT)

Та же архитектура, другой рецепт обучения:
- Убрали задачу **NSP** (оказалась не нужной и иногда вредила)
- Ввели **динамическое маскирование** (маски генерируются заново каждую эпоху, а не фиксируются один раз)
- Радикально увеличили batch size (256 → 8000), объём данных (16 ГБ → 160 ГБ) и время обучения

Результат: качество на бенчмарках значительно выросло, хотя архитектура не менялась.

### 6. DistilBERT (Knowledge Distillation)

Проблема: Трансформеры тяжелы для продакшена. Решение — **дистилляция знаний**:
- Большая модель-«учитель» (BERT Base)
- Маленькая модель-«студент» (половина слоёв учителя)

Студент обучается не просто предсказывать правильные ответы, а максимально приблизить распределения Softmax и внутренние hidden states учителя.

Итог: DistilBERT сохраняет **97% качества** BERT, но работает **на 60% быстрее** и потребляет меньше памяти.

## Формула / Схема

**Правило маскирования MLM:**

| Действие | Доля из 15% выбранных токенов |
|----------|-------------------------------|
| Заменить на `[MASK]` | 80% |
| Заменить на случайный токен | 10% |
| Оставить без изменений | 10% |

**Сравнение BERT и GPT:**

| | BERT (Encoder-only) | GPT (Decoder-only) |
|--|--|--|
| **Контекст** | Двунаправленный | Левосторонний |
| **Задача обучения** | MLM (маскирование) | CLM (следующее слово) |
| **Применение** | Классификация, NER, QA, поиск | Генерация текста |
| **Примеры** | BERT, RoBERTa, DistilBERT | GPT-4, LLaMA, Claude |

**Классификация через `[CLS]`:**

$$\Large h_{\text{CLS}} = \text{BERT}([\text{CLS}], x_1, \ldots, x_n, [\text{SEP}])_0$$

$$\Large \hat{y} = \text{softmax}(W h_{\text{CLS}} + b)$$

где:
- $h_{\text{CLS}}$ — выход последнего слоя на позиции `[CLS]`
- индекс $0$ — первая позиция последовательности
- $W, b$ — параметры классификационной головы

## Короткий пример

```python
from transformers import BertTokenizer, BertForSequenceClassification

tokenizer = BertTokenizer.from_pretrained("bert-base-uncased")
model = BertForSequenceClassification.from_pretrained("bert-base-uncased", num_labels=2)

# Fine-tuning: обучаем линейный классификатор поверх эмбеддинга [CLS] токена
inputs = tokenizer("This movie was absolutely great!", return_tensors="pt")
outputs = model(**inputs)  # outputs.logits.shape: [1, 2]
```

## Типичные ошибки

- **Использовать BERT для генерации длинных текстов:** BERT — только Энкодер. Он отлично понимает, классифицирует и ищет ответы, но не умеет авторегрессионно генерировать текст. Для этого нужен Decoder (GPT) или Encoder-Decoder (BART, T5).
- **Считать, что BERT обучается предсказывать следующее слово:** грубая ошибка. BERT видит весь текст целиком (и левый, и правый контекст) и предсказывает «выколотые» слова из середины — никакой левосторонней маски нет.
- **Думать, что `[CLS]` изначально содержит смысл текста:** на входе это просто специальный эмбеддинг. Смысл всей последовательности появляется только после прохождения через слои Self-Attention.

## Каверзные вопросы

> [!question] Зачем для классификации текста берётся эмбеддинг не усреднённый по всем словам, а только от токена [CLS]?
> Токен `[CLS]` добавлен специально, и через механизм Self-Attention его эмбеддинг на последнем слое агрегирует информацию обо всём предложении. Усреднение по всем токенам (mean pooling) тоже работает, но `[CLS]` обучен именно для предсентенциальной классификации.

## Проверка себя

- Зачем в GLUE несколько разных задач — на 1 предложение и на пары предложений?
- Почему инженеры BERT не заменяли 100% выбранных токенов на `[MASK]`?
- Какую задачу предобучения исследователи RoBERTa полностью убрали, добившись роста метрик?
- На что, помимо финальных классов, смотрит модель-«студент» при обучении DistilBERT?
