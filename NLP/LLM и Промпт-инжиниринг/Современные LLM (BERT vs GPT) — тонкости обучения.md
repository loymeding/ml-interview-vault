# Современные LLM: BERT vs GPT и тонкости обучения

> [!abstract] Суть
> Оригинальный Трансформер состоит из Encoder и Decoder. Современные LLM разделились на два лагеря: **BERT** (только Encoder, двунаправленный контекст, хорош для анализа текста) и **GPT** (только Decoder, авторегрессионная генерация). Для стабильного обучения гигантских моделей применяют Warm-up шага обучения и вычисления в половинной точности (Mixed Precision).

## Ответ

### 1. BERT vs GPT: два лагеря трансформеров

В оригинальном Трансформере Encoder обрабатывал исходный текст целиком, а Decoder пословно генерировал перевод. Выяснилось, что блоки можно использовать по отдельности.

| | BERT (Encoder) | GPT (Decoder) |
|--|--|--|
| **Контекст** | Двунаправленный (видит весь текст) | Однонаправленный (только предыдущие слова) |
| **Self-Attention** | Обычный — видит все токены | Masked — маскирует будущее |
| **Задача обучения** | MLM: предсказать замаскированные слова | CLM: предсказать следующее слово |
| **Применение** | Классификация, NER, QA, поиск | Генерация текста |
| **Примеры** | BERT, RoBERTa, DistilBERT | GPT-4, LLaMA, Claude |

**Почему Decoder маскирует будущее?** Задача генерации требует предсказания токена $t_{i+1}$ строго на основе $t_1, \ldots, t_i$. Без маски токен на позиции $i$ через матрицы Q, K, V «подсматривал» бы позицию $i+1$ при обучении — модель просто выучила бы копирование вместо генерации.

### 2. Warm-up оптимизатора

При обучении модели с сотнями миллиардов параметров постоянный высокий Learning Rate катастрофичен: веса инициализированы случайно, градиенты на первых шагах огромны и хаотичны — обучение мгновенно уходит в нестабильное состояние.

**Решение — Warm-up:** LR линейно растёт от нуля до $\text{LR}_\text{max}$ в течение первых $t_\text{warm}$ шагов, затем плавно убывает по косинусному закону или linear decay.

```
LR
|        /\
|       /  \____
|      /        \___
|_____/              \___
     warm          конец обучения
```

### 3. Mixed Precision (смешанная точность)

Главный враг при обучении LLM — нехватка VRAM. Хранение весов и состояний оптимизатора для миллиардов параметров в Float32 невозможно.

| Компонент | Точность |
|-----------|----------|
| Forward и Backward pass | Float16 / BFloat16 |
| Мастер-веса оптимизатора | Float32 (чтобы не терять мелкие обновления) |

Ускорение: **2–3×**, потребление VRAM: вдвое ниже.

Float32 для мастер-весов обязателен: при суммировании крошечных обновлений ($\sim 10^{-7}$) в Float16 точности не хватает, и веса перестают обновляться.

## Формула / Схема

**Warm-up + косинусное затухание:**

$$\Large \text{LR}(t) = \text{LR}_\text{max} \cdot \min\!\left(\frac{t}{t_\text{warm}},\; \frac{1}{2}\!\left[1 + \cos\!\left(\pi \cdot \frac{t - t_\text{warm}}{T - t_\text{warm}}\right)\right]\right)$$

где:
- $t$ — текущий шаг обучения
- $t_\text{warm}$ — количество шагов фазы Warm-up
- $T$ — общее число шагов обучения
- $\text{LR}_\text{max}$ — пиковое значение Learning Rate

## Короткий пример

Аналогия — прогрев автомобиля в мороз: газ сразу в пол → двигатель заглохнет. Несколько минут на холостых (Warm-up) → масло распределилось → трогаемся плавно.

Практика GPT-3 (175 млрд параметров): 6 000 шагов Warm-up из 300 000 суммарных, $\text{LR}_\text{max} = 6 \times 10^{-5}$.

## Типичные ошибки

- **Использовать BERT для генерации:** архитектура физически не приспособлена — BERT предсказывает замаскированные слова в готовом предложении, а не генерирует слева направо.
- **Обучать Трансформер без Warm-up:** случайная инициализация + большой LR → NaN в функции потерь на первых шагах.
- **Хранить всё в Float16:** мастер-веса Adam (первый и второй момент) должны быть в Float32, иначе мелкие обновления округляются до нуля.

## Каверзные вопросы

> [!question] Зачем в Decoder-only моделях (GPT) маскировать будущее при Attention?
> Задача генерации требует предсказания токена $t_{i+1}$ только на основе предыдущих ($t_1, \ldots, t_i$). Без маски токен на позиции $i$ через Q, K, V «подсматривал» бы $i+1$ во время обучения — модель выучила бы копирование ответов из будущего, потеряв способность генерировать.
