# Продвинутые Seq2Seq (T5, BART) и RAG-системы

> [!abstract] Суть
> Пока OpenAI масштабировала Decoder-only GPT, параллельно развивались **полные Encoder-Decoder** архитектуры. **BART** объединил двунаправленный энкодер BERT и авторегрессионный декодер GPT, обучаясь восстанавливать сильно зашумленный текст. **T5** унифицировал все NLP-задачи в единый формат **Text-to-Text** с текстовыми префиксами. Для борьбы с галлюцинациями LLM индустриальным стандартом стал **RAG** — генерация, дополненная поиском по внешней базе знаний.

## Ответ

### 1. BART (Bidirectional and Auto-Regressive Transformers)

BART берёт лучшее из двух миров:
- **Энкодер** — двунаправленный (как в BERT): хорошо понимает контекст
- **Декодер** — авторегрессионный (как в GPT): хорошо генерирует текст

Задача предобучения: восстановить **сильно зашумленный** исходный текст. Виды шума:
1. **Маскирование токенов** (как в BERT MLM)
2. **Удаление токенов** (модель должна понять, что слово пропало — в отличие от BERT нет явного `[MASK]`)
3. **Text Infilling** — замена целого куска текста **одним** токеном-маской
4. **Sentence Permutation** — перестановка предложений местами
5. **Document Rotation** — документ начинается со случайного слова, нужно найти истинное начало

**Зачем Sentence Permutation для суммаризации?** Суммаризация требует связывать факты из начала и конца документа. Восстановление порядка предложений заставляет Декодер выучивать **глобальную логическую макро-структуру** всего текста, а не только локальный синтаксис.

### 2. T5 (Text-to-Text Transfer Transformer)

Google унифицировала все NLP-задачи: **любая задача = генерация текста по тексту**.

Примеры:
- Перевод: `translate English to German: That is good.` → `Das ist gut.`
- Классификация (CoLA): `cola sentence: The course is jumping well.` → `unacceptable`
- Суммаризация: `summarize: [длинный текст]` → краткое изложение

**Span Corruption (метод предобучения T5):** в тексте удаляются целые последовательности токенов (spans), заменяемые sentinel-маркерами (`<X>`, `<Y>`, ...). Декодер восстанавливает только пропущенные куски, а не весь текст.

**Провал в переводе:** T5 обучалась исключительно на английском корпусе C4. Несмотря на 11B параметров, этого оказалось недостаточно для качественного перевода — что доказывает: качество данных так же важно, как и размер модели.

### 3. RAG (Retrieval-Augmented Generation)

Даже GPT-3 (175B) галлюцинирует и не знает событий после даты обрезки. **RAG** — индустриальный стандарт:

1. **Retrieval:** по запросу пользователя делается поиск по внешнему индексу (корпоративная Wiki, база документов)
2. Найденные релевантные параграфы вставляются прямо в **контекст (Prompt)** языковой модели
3. **Generation:** LLM генерирует ответ, опираясь строго на предоставленный контекст

Результат: в разы меньше галлюцинаций, возможность ссылаться на источники, актуальные знания без дорогого переобучения.

### 4. Практика: Экосистема Hugging Face

Для Fine-tuning BART/T5 больше не нужно писать циклы с нуля.

```python
from transformers import (BartForConditionalGeneration, BartTokenizer,
                           Seq2SeqTrainer, Seq2SeqTrainingArguments,
                           DataCollatorForSeq2Seq)

# 1. Загрузка модели и токенизатора
model = BartForConditionalGeneration.from_pretrained("facebook/bart-base")
tokenizer = BartTokenizer.from_pretrained("facebook/bart-base")

# 2. DataCollator — динамический паддинг до макс. длины в батче
data_collator = DataCollatorForSeq2Seq(tokenizer, model=model)

# 3. Trainer берёт на себя backward(), step() и логирование
training_args = Seq2SeqTrainingArguments(
    output_dir="./results",
    predict_with_generate=True  # считать метрики по сгенерированному тексту, не по логитам
)
trainer = Seq2SeqTrainer(model=model, args=training_args,
                         train_dataset=train_data, data_collator=data_collator)
trainer.train()

# 4. Инференс с Beam Search
inputs = tokenizer("summarize: " + long_text, return_tensors="pt")
ids = model.generate(inputs["input_ids"], num_beams=4, min_length=10)
print(tokenizer.decode(ids[0], skip_special_tokens=True))
```

**Метрика ROUGE:** для суммаризации и перевода — доля пересечения n-грамм между сгенерированным текстом и эталонным референсом (аналог BLEU для генерации).

## Формула / Схема

**T5 унификация задач:**

| Задача | Префикс + вход | Декодер генерирует |
|--------|----------------|-------------------|
| Перевод | `translate English to German: Hello` | `Hallo` |
| Классификация | `cola sentence: The dog run fast` | `unacceptable` |
| Суммаризация | `summarize: [длинный текст]` | краткий текст |

**Span Corruption в T5:**
```
Исходный:    "The cat sat on the mat today"
Зашумлённый: "The <X> on <Y> today"
Цель декодера: "<X> cat sat <Y> the mat"
```

## Типичные ошибки

- **Использовать BERT для суммаризации или перевода:** BERT — только Энкодер, не способен генерировать длинные тексты. Нужны BART, T5 (Encoder-Decoder) или GPT (Decoder-only).
- **Подавать в T5 текст без префикса задачи:** без триггерного префикса (`summarize:`, `translate...:`) модель не поймёт, что от неё требуется — результат будет непредсказуемым мусором.
- **Использовать Greedy Search для суммаризации:** в `.generate()` всегда включайте `num_beams=4` для качественного связного текста.

## Каверзные вопросы

> [!question] Зачем при предобучении BART используется «перестановка предложений» (Sentence Permutation)?
> При суммаризации модель должна вычленять главную мысль, связывая факты из начала и конца документа. Предсказание пропущенных слов (как в BERT) учит только локальному синтаксису. Задача восстановления правильного порядка предложений заставляет Декодер выучивать **логическую макро-структуру** документа целиком.

> [!question] Почему T5 11B, побившая рекорды GLUE, провалилась в задачах машинного перевода?
> T5 обучалась исключительно на английском корпусе C4. Это доказывает: **качество данных так же важно, как и размер модели** — знаний из одного языка недостаточно для качественного перевода на другой.
