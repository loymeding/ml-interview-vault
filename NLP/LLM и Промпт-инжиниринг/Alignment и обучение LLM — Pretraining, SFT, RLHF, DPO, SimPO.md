# Alignment и обучение LLM — Pretraining, SFT, RLHF, DPO, SimPO

> [!abstract] Суть
> Современная LLM обычно проходит три крупных этапа: pretraining учит предсказывать следующий токен и формирует базовые знания, SFT учит следовать инструкциям, а alignment по предпочтениям делает ответы более полезными, безопасными и соответствующими ожиданиям пользователя.

## Ответ

### 1. Pretraining

Pretraining обучает модель на больших корпусах в постановке next-token prediction:

$$\Large L_{\text{LM}} = -\sum_{t=1}^{T}\log p_\theta(x_t \mid x_{<t})$$

где:
- $x_t$ — истинный следующий токен;
- $x_{<t}$ — предыдущий контекст;
- $p_\theta$ — распределение модели.

Этот этап создаёт base model. Она хорошо продолжает текст, знает факты и языковые паттерны, но ещё не обязана отвечать в формате ассистента.

### 2. SFT

SFT (Supervised Fine-Tuning) обучает модель на парах `instruction -> answer`. Модель видит хорошие ответы и учится:
- следовать инструкции;
- держать формат;
- отвечать в диалоговом стиле;
- решать типовые пользовательские задачи.

SFT переводит base model в instruct/chat режим. Без SFT RLHF будет нестабильным: сырая модель выдаёт много странных продолжений, и preference learning сложнее использовать эффективно.

### 3. Зачем SFT перед RLHF

SFT сужает пространство действий. После него модель уже умеет писать осмысленные ответы, а RLHF не учит её базовому формату с нуля, а тонко корректирует предпочтения: полезность, безопасность, вежливость, отказ от плохих ответов.

Если пропустить SFT, reward model будет сравнивать много низкокачественных ответов, а RL-оптимизация может стать шумной и склонной к reward hacking.

### 4. Классический RLHF с PPO

Классический RLHF:
1. собирают пары ответов и человеческие предпочтения;
2. обучают reward model, которая оценивает качество ответа;
3. оптимизируют policy через PPO с KL-штрафом к reference model.

Интуиция KL-штрафа:

$$\Large L = -\mathbb{E}[R(x,y)] + \beta \, KL(\pi_\theta(y|x) \| \pi_{\text{ref}}(y|x))$$

где:
- $R(x,y)$ — reward ответа $y$ на запрос $x$;
- $\pi_\theta$ — текущая политика;
- $\pi_{\text{ref}}$ — reference model, обычно SFT-модель;
- $\beta$ — сила ограничения, чтобы модель не ушла слишком далеко.

Минус PPO: дорого и сложно. Нужно держать policy, reference, reward model и часто value model.

### 5. DPO

DPO (Direct Preference Optimization) упрощает alignment. Вместо отдельной reward model и online RL используется прямая функция потерь по парам `chosen/rejected`.

Идея: повысить вероятность предпочитаемого ответа относительно отвергнутого, сохранив регуляризацию к reference model.

Плюсы:
- похоже на supervised fine-tuning;
- меньше моделей в памяти;
- стабильнее и проще инженерно;
- хорошо работает на offline preference data.

### 6. SimPO

SimPO ещё сильнее упрощает схему: убирает явную reference model и использует нормализацию по длине, чтобы не поощрять ответы просто за то, что они длиннее.

Главная идея: preference loss должен сравнивать качество ответов, а не суммарную log-prob, которая растёт/падает вместе с длиной.

### 7. PPO vs DPO vs SimPO

| Метод | Что нужно | Плюсы | Минусы |
|---|---|---|---|
| PPO/RLHF | reward model, reference, policy, value | гибкость | дорого, сложно тюнить |
| DPO | chosen/rejected пары и reference | просто, стабильно | меньше гибкости, зависит от качества пар |
| SimPO | chosen/rejected пары | ещё проще, нет reference | нужно аккуратно тюнить margin/length norm |

## Формула / Схема

**DPO в смысловой форме:**

$$\Large L_{\text{DPO}} = -\log \sigma\!\left(\beta \left[\log\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \log\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right]\right)$$

где:
- $x$ — prompt;
- $y_w$ — preferred/chosen answer;
- $y_l$ — rejected answer;
- $\pi_\theta$ — обучаемая модель;
- $\pi_{\text{ref}}$ — reference model;
- $\beta$ — сила регуляризации.

## Короткий пример

Если base model продолжает:

```text
Пользователь: Объясни BatchNorm
Модель: BatchNorm BatchNorm BatchNorm...
```

SFT учит её отвечать в формате объяснения. RLHF/DPO затем учит, какой из нескольких корректных ответов люди предпочитают: более точный, структурированный, безопасный и без лишней воды.

## Типичные ошибки

- **Думать, что RLHF добавляет знания:** в основном он меняет поведение и предпочтения, а не фундаментально расширяет знания.
- **Переусердствовать с alignment:** модель может стать слишком осторожной, шаблонной и менее разнообразной.
- **Учить reward model на смещённых предпочтениях:** модель начнёт оптимизировать не качество, а bias разметки.
- **Путать SFT и pretraining:** SFT не учит язык с нуля, а адаптирует уже обученную LLM к формату задач.

## Каверзные вопросы

> [!question] Почему base model не является хорошим ассистентом сразу после pretraining?
> Она обучалась продолжать текст, а не выполнять инструкции. Если prompt похож на диалог, base model может продолжить диалог любым статистически вероятным образом, включая ответы пользователя, рассуждения или обрывки разметки.

> [!question] Почему DPO проще PPO?
> DPO оптимизирует offline preference loss как обычный supervised training. Не нужен rollout policy в RL-среде, value model и отдельная reward model в основном цикле оптимизации.
