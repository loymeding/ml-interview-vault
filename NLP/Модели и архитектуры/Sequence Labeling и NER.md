# Sequence Labeling и NER

> [!abstract] Суть
> Sequence labeling — это задачи, где метка предсказывается для каждого токена, а не для всего текста. NER — частный случай: нужно найти именованные сущности и определить их типы, например `PERSON`, `ORG`, `LOC`.

## Ответ

### 1. Что такое sequence labeling

В классификации текста модель выдаёт одну метку на весь документ:

```text
"фильм отличный" -> positive
```

В sequence labeling модель выдаёт метку на каждый токен:

```text
"Илон Маск основал SpaceX"
Илон -> B-PER
Маск -> I-PER
основал -> O
SpaceX -> B-ORG
```

Типичные задачи:
- NER;
- POS-tagging;
- chunking;
- slot filling в диалоговых системах;
- извлечение терминов.

### 2. BIO-разметка

BIO-кодирование показывает границы сущностей:
- `B-X` — начало сущности типа `X`;
- `I-X` — продолжение сущности типа `X`;
- `O` — токен вне сущности.

Это нужно, чтобы отличать соседние сущности одного типа и много токенов внутри одной сущности.

### 3. Модели для NER

Классический пайплайн:
- признаки токена и контекста;
- CRF, HMM или линейные модели.

Нейросетевой пайплайн:
- BiLSTM/GRU читает контекст слева и справа;
- CRF-слой сверху контролирует допустимые переходы меток;
- BERT/encoder-only transformer даёт контекстные embeddings токенов;
- token-classification head предсказывает метку каждого токена.

BiLSTM и BERT полезны, потому что тип сущности часто зависит от правого контекста:

```text
"Apple выпустила обновление" -> ORG
"apple лежит на столе" -> не ORG
```

### 4. Зачем CRF поверх BiLSTM/BERT

Если предсказывать метку каждого токена независимо, можно получить невозможную последовательность:

```text
O I-PER I-PER
```

`I-PER` не должен начинаться без `B-PER`. CRF учитывает переходы между соседними метками и выбирает наиболее правдоподобную последовательность целиком.

### 5. Оценка качества

Для NER обычно считают entity-level Precision/Recall/F1: сущность засчитывается, только если правильно найдены и границы, и тип.

Token-level accuracy может быть обманчивой: большинство токенов имеют метку `O`, поэтому модель, которая всегда предсказывает `O`, может иметь высокую accuracy и нулевую пользу.

## Формула / Схема

**Token classification:**

$$\Large \hat{y}_t = \text{softmax}(W h_t + b)$$

где:
- $h_t$ — контекстное представление токена $t$;
- $W,b$ — параметры классификационной головы;
- $\hat{y}_t$ — распределение по меткам для токена.

**CRF score последовательности:**

$$\Large s(x,y) = \sum_{t=1}^{T} A_{y_{t-1}, y_t} + \sum_{t=1}^{T} P_{t,y_t}$$

где:
- $A_{y_{t-1}, y_t}$ — score перехода между метками;
- $P_{t,y_t}$ — score метки $y_t$ для токена $t$;
- $T$ — длина последовательности.

## Короткий пример

В резюме:

```text
"Работал в Яндексе с 2020 года"
Яндексе -> B-ORG
2020 -> B-DATE
```

Для downstream-задачи важно не просто понять тональность текста, а вытащить структурированные поля.

## Типичные ошибки

- **Считать token accuracy главной метрикой:** из-за доминирования `O` она часто завышена.
- **Не выравнивать labels после subword-токенизации:** слово может распасться на несколько subword-токенов, и нужно решить, как размечать части.
- **Использовать bidirectional модель для авторегрессионной генерации:** для NER это нормально, для генерации будущий контекст недоступен.

## Каверзные вопросы

> [!question] Почему BiLSTM можно использовать для NER, но нельзя для decoder генерации?
> В NER весь текст уже известен, поэтому правый контекст доступен. В авторегрессионной генерации будущих токенов ещё нет, смотреть справа налево нельзя.

> [!question] Почему CRF может улучшить качество поверх BERT?
> BERT даёт сильные token embeddings, но независимая softmax-голова не знает ограничений переходов меток. CRF добавляет последовательностную согласованность.
