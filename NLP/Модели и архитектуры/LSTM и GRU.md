# LSTM и GRU (Сети с долгой краткосрочной памятью и вентильные рекуррентные блоки)

> [!abstract] Суть
> LSTM и GRU — это усложненные версии рекуррентных нейросетей, созданные для решения проблемы затухающих градиентов и захвата долгосрочных зависимостей. Они используют механизм «вентилей» (gates), состоящих из слоя сигмоиды и поэлементного умножения, чтобы выборочно пропускать, забывать или обновлять информацию.

## Ответ

**Проблема затухающих градиентов (на основе "Нейросети для работы с последовательностями")**
В классической RNN на каждом шаге скрытое состояние многократно умножается на одну и ту же матрицу весов. Если собственные значения этой матрицы меньше $1$, градиенты при обратном распространении сквозь время экспоненциально стремятся к нулю. Из-за этого модель не может связать причину и следствие, если между ними много шагов (например, в тексте: *"Кот, который жил... любил ___"* — к концу предложения сеть забывает, что речь шла о коте).

**Архитектура LSTM (Long Short-Term Memory)**
Предложена в 1997 году. LSTM разделяет память на два потока:
1. **Cell State ($C_t$)** — «долгосрочная память» (или состояние блока). Информация течет по ней практически без изменений линейно, что спасает градиенты от затухания.
2. **Hidden State ($h_t$)** — «краткосрочная память», выдаваемая наружу сети.

Для контроля потока информации LSTM использует три вентиля (gates):
*   **Forget gate (вентиль забывания, $f_t$):** Смотрит на $h_{t-1}$ и $x_t$ и решает, какую информацию из прошлой долгосрочной памяти $C_{t-1}$ нужно стереть (выдает от $0$ до $1$).
*   **Input gate (вентиль входа, $i_t$):** Решает, какие значения из нового входа-кандидата $\tilde{C}_t$ нужно сохранить в долгосрочную память.
*   **Output gate (вентиль выхода, $o_t$):** Решает, какую часть информации из обновленного Cell State $C_t$ нужно выдать в качестве нового краткосрочного состояния $h_t$.

**Архитектура GRU (Gated Recurrent Unit)**
Появилась в 2014 году как упрощенная версия LSTM. 
* В ней нет отдельного Cell State, вся память хранится в едином скрытом состоянии $h_t$.
* Вместо трех вентилей используется два: **Reset gate ($r_t$)** решает, сколько прошлой информации сбросить, а **Update gate ($z_t$)** выполняет функции сразу двух вентилей LSTM (input и forget), решая баланс между старой и новой информацией.
* **Итог:** Меньше параметров, учится быстрее, а качество часто сопоставимо с LSTM.

**Обратное распространение сквозь время (BPTT)**
В отличие от обычных сетей, в RNN один и тот же набор весов $W_h$ используется на каждом шаге. Градиент по $W_h$ суммируется по всем шагам:

$$\Large \frac{\partial L}{\partial W_h} = \sum_{t=1}^{T} \frac{\partial L_t}{\partial h_t} \cdot \prod_{k=t+1}^{T} \frac{\partial h_k}{\partial h_{k-1}}$$

где:
- $T$ — длина последовательности
- $\frac{\partial L_t}{\partial h_t}$ — локальный градиент на шаге $t$
- $\prod_{k} \frac{\partial h_k}{\partial h_{k-1}}$ — произведение якобианов перехода между состояниями

**Почему градиенты затухают:** $\frac{\partial h_k}{\partial h_{k-1}} = W_h^T \cdot \text{diag}(\tanh'(h_{k-1}))$. Если максимальное собственное значение $W_h$ меньше 1, произведение за $T$ шагов экспоненциально → 0. LSTM обходит это через Cell State, по которому градиент течёт почти без умножения.

**Инженерная практика: Teacher Forcing**
При обучении генеративных RNN (языковых моделей, Seq2Seq-декодера) мы предсказываем слово $y_1$, подаём его на вход и предсказываем $y_2$. Если в начале обучения сеть выдала мусор вместо $y_1$ — следующий шаг будет строиться на этом мусоре, что разрушает обучение.

**Teacher Forcing:** на этапе тренировки на вход следующего шага принудительно подаётся **истинное** слово из датасета, независимо от предсказания сети. Это радикально ускоряет и стабилизирует сходимость.

**Двунаправленные RNN (Bi-RNN)**
Классические RNN и LSTM читают последовательность только слева направо — при обработке токена правый контекст им недоступен. Двунаправленная архитектура запускает **два независимых RNN** параллельно: один — слева направо ($\overrightarrow{h_t}$), второй — справа налево ($\overleftarrow{h_t}$). На каждом шаге скрытые состояния конкатенируются:

$$\Large \hat{h}_t = [\,\overrightarrow{h_t}\; \|\; \overleftarrow{h_t}\,]$$

Это удваивает размерность выхода, но позволяет каждому токену «видеть» весь контекст. Применение: Named Entity Recognition, QA, задачи полного контекста. BERT реализует ту же идею через двунаправленный Self-Attention.

## Формула / Схема

**Ключевое обновление памяти в LSTM:**
$$\Large C_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_t$$

где:
- $C_t$ — новое состояние долгосрочной памяти (Cell State)
- $C_{t-1}$ — предыдущее Cell State
- $f_t \in [0,1]^n$ — Forget gate: маска забывания (0 = стереть, 1 = сохранить)
- $i_t \in [0,1]^n$ — Input gate: маска записи новой информации
- $\tilde{C}_t$ — кандидат на запись в память (tanh-выход)
- $\odot$ — поэлементное (Hadamard) умножение

**Ключевое обновление памяти в GRU:**
$$\Large h_t = (1 - z_t) \odot h_{t-1} + z_t \odot \tilde{h}_t$$

где:
- $h_t$ — новое скрытое состояние
- $h_{t-1}$ — предыдущее скрытое состояние
- $z_t \in [0,1]^n$ — Update gate: при $z_t=0$ оставляем старое, при $z_t=1$ берём новое
- $\tilde{h}_t$ — кандидат на новое скрытое состояние (tanh-выход с учётом Reset gate)
- $\odot$ — поэлементное умножение

## Короткий пример

Реализация и разница выходов в PyTorch (на основе материалов курса):
```python
import torch
import torch.nn as nn

# LSTM возвращает ТРИ тензора: выходы на всех шагах, и кортеж (последнее скрытое, последнее состояние ячейки)
lstm = nn.LSTM(input_size=10, hidden_size=20, batch_first=True)
output_lstm, (hn_lstm, cn_lstm) = lstm(x)

# GRU возвращает ДВА тензора: выходы на всех шагах и последнее скрытое состояние
gru = nn.GRU(input_size=10, hidden_size=20, batch_first=True)
output_gru, hn_gru = gru(x)
```

## Типичные ошибки

*   **Использовать ReLU в рекуррентных сетях без нормализации:** ReLU не ограничивает выход сверху. Скрытое состояние $h_t$ рекурсивно умножается на матрицу весов сотни раз — активации моментально уходят в бесконечность (Exploding Activations). Стандарт для RNN — ограниченный `tanh` (от −1 до 1).
*   **Использовать tanh внутри вентилей LSTM/GRU:** Вентили ($f_t$, $i_t$, $o_t$) играют роль «рубильников» с диапазоном [0, 1], где 0 = «закрыть», 1 = «открыть». Функция `tanh` выдаёт от −1 до 1, что нарушит логику фильтрации. В вентилях должна быть строго **сигмоида**.
*   **Путаница в инициализации скрытых состояний:** Правильно — нулями, контекст до первого токена пуст.
*   **Ожидание от GRU кортежа памяти:** Вызов `nn.GRU` возвращает только `output` и `hn`. Попытка распаковать кортеж `(hn, cn)` как в LSTM приведёт к ошибке.

## Каверзные вопросы

> [!question] Мы подаём батч текстов: одно предложение длиной 10 токенов, второе — 15. Нейросети работают с тензорами фиксированного размера. Как прогнать это через RNN?
> Тексты **выравниваются (padding)** по самому длинному: к короткому добавляются PAD-токены (нули) до длины 15. Затем, чтобы RNN не обновляла скрытое состояние на бессмысленных нулях, в PyTorch используется `pack_padded_sequence` — он заставляет сеть физически остановиться на 10-м токене для первого предложения.

> [!question] Почему вентили (gates) используют именно функцию активации Sigmoid, а преобразование кандидатов в память — Tanh?
> Смысл вентилей (forget, input, output, update, reset) — фильтрация информации. Им нужно ответить на вопрос "да/нет/частично", поэтому используется сигмоида, область значений которой от $0$ до $1$ (где $0$ — полностью забыть/стереть, $1$ — полностью пропустить). Функция `tanh` используется для формирования самой памяти, так как её область значений от $-1$ до $1$ позволяет центрировать данные, добавлять как положительные, так и отрицательные векторы признаков, и помогает стабилизировать градиенты.
