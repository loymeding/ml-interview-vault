# SKILL — планирование

Этот файл — инструкция для Claude по генерации планов обучения.
Пользователь обращается: *«составь план на неделю»*, *«что мне делать сегодня»*, *«успеваю ли я»*.

---

## Шаг 1 — Собери контекст (читай все эти файлы)

### Дедлайны и режим
- `Планировщик/🎯 Цели и сроки.md` → дата интервью, целевые даты по разделам, часы в день

### Самооценка
- `Планировщик/📊 Мой уровень.md` → субъективная картина по каждому разделу

### Реальный прогресс по карточкам
Прочитай frontmatter всех карточек и собери поле `готовность` по разделам:
- `Classic Machine Learning/**/*.md` (кроме служебных файлов)
- `Deep Learning/**/*.md`
- `NLP/**/*.md`
- `SQL/**/*.md`
- `Python/**/*.md`
- `А-Б тесты/**/*.md`

Служебные файлы (исключить из подсчёта): `🏠 Главная`, `🗺️ Индекс`, `📅 По дате`, `📚 Источники`, `🔎 На ревью`, `🧩 Карта связей`, `Банк вопросов`, `SKILL`, `CLAUDE`, шаблоны.

### Аналитика интервью
- `Classic Machine Learning/📊 Аналитика/📈 Дашборд.md` → средние баллы по темам, слабые места

### Interview Questions (конкретные вопросы для плана)
Для каждой темы, которую планируешь включить в неделю, прочитай соответствующий файл в `[Раздел]/Interview Questions/[тема].md`.

Формат файла:
```yaml
## Q001
type: fact | trap | compare | chain | scenario | debug | tradeoff | system_design
difficulty: junior | middle | senior
key_concepts: [концепт1, концепт2]
text: текст вопроса
follow_up:
  - уточняющий вопрос
```

Из этого файла выбирай 2–3 вопроса для включения в дневной план (логика выбора — в Шаге 3).

### LeetCode
- `LeetCode/📋 Задачи.md` → статистика (решено / всего), пустые попытки = без кода

### Предыдущий план (если есть)
- `Планировщик/Недели/` → последний файл недели → что было запланировано
- `Планировщик/Дни/` → файлы дней текущей недели → что выполнено (отмеченные `[x]`)

## Шаг 1.5 — Проверь и сгенерируй Interview Questions для тем недели

Перед построением плана проверь: у каждой темы, которую планируешь на неделю, должен быть файл в `[Раздел]/Interview Questions/`.

**Алгоритм:**
1. Определи список тем для недели (из Банка вопросов + слабых тем аналитики)
2. Для каждой темы проверь наличие файла `Interview Questions/[тема].md`
3. Если файла нет — запусти генерацию **до** создания плана:
   ```
   python "C:\Рабочий стол\interview-tool\generate_questions.py" \
     --vault "C:\Рабочий стол\DataScienceDB" \
     --section "Deep Learning" \
     --topics "Название темы"
   ```
   Параметр `--section` — название раздела vault (`Classic Machine Learning`, `Deep Learning`, `NLP` и т.д.)
4. Если карточки для темы ещё не существует (тема только запланирована, раздел пустой) — вместо `❓ Вопросы` ставь задачу `📝 Создать карточку: [тема]` и не пытайся генерировать вопросы без карточки

## Шаг 2 — Рассчитай темп

### Для каждого раздела:
```
осталось_тем = кол-во карточек с готовностью < целевой %
дней_до_дедлайна = дата_завершения_раздела - сегодня
задач_в_день = осталось_тем / дней_до_дедлайна
```

### Флаги предупреждений:
- 🔴 **Критично**: задач_в_день > доступных_часов / 0.5 (не успеваем при любом режиме)
- 🟡 **Напряжённо**: задач_в_день > доступных_часов / 1.0 (успеем, но без запаса)
- 🟢 **Норма**: есть запас

### Сообщи пользователю:
- Общий статус: успеваем / напряжённо / не успеваем
- По каким разделам проблема и насколько
- Конкретное предложение: «добавить 1 час в день» или «сдвинуть дедлайн раздела X на 2 недели»

## Шаг 3 — Построй план

### Принципы приоритизации

1. **Приоритет из `🎯 Цели и сроки.md`** — разделы с меньшим числом идут первыми
2. **Слабые темы из аналитики** — темы с баллом < 3.0 в дашборде → повторение
3. **Spaced repetition** — темы, которые давно не повторялись (смотри дату `создано` + аналитику)
4. **LeetCode** — 1 задача в день: сначала Easy без типа/алгоритма (незаполненные поля), потом Medium

### Типы задач на день

| Тип | Обозначение в плане | Примерное время |
|-----|---------------------|-----------------|
| Прочитать карточку | `📖 Карточка` | 20–30 мин |
| Ответить на конкретные вопросы | `❓ Вопросы` | 20–30 мин |
| Запустить интервью-симулятор | `🎤 Интервью` | 25–40 мин |
| Решить задачу LeetCode | `💻 LeetCode` | 20–45 мин |
| Повторить старую тему | `🔁 Повторение` | 10–20 мин |
| Создать карточку (нет материала) | `📝 Создать карточку` | 30–60 мин |

### Как выбирать вопросы для задачи `❓ Вопросы`

Читай `Interview Questions/[тема].md` и выбирай 2–3 вопроса по следующей логике:

**По сложности** — ориентируйся на текущий уровень пользователя по разделу:
- Тема новая / уровень низкий → 2 junior + 1 middle
- Тема знакома, уровень средний → 1 junior + 2 middle
- Тема уже отрабатывалась в симуляторе → 1 middle + 1–2 senior

**По типу** — в каждый день включай разнообразие:
- Обязательно 1 `fact` или `chain` (проверка базы)
- Обязательно 1 `trap` или `scenario` (применение)
- Опционально 1 `debug` или `tradeoff` (углубление)

**В дневном файле** — записывай не просто тему, а конкретные вопросы:
```markdown
- [ ] ❓ Вопросы: [[Backpropagation]]
  - Q001 (junior · fact): Объясни Chain Rule и роль локального/глобального градиента
  - Q002 (junior · trap): Забыли optimizer.zero_grad() — это ошибка?
  - Q005 (middle · scenario): 20-слойная сеть с sigmoid перестала учиться — что происходит?
```

### Формула дня при разных нагрузках

**2 часа:** 1 Карточка + 1 Вопросы + 1 LeetCode
**3–4 часа:** 1–2 Карточки + 1 Вопросы + 1 Интервью + 1 LeetCode
**5–6 часов:** 2 Карточки + 1 Вопросы + 1 Интервью + 1 LeetCode + 1 Повторение

## Шаг 5 — Диалог и корректировка

После генерации плана:
- Кратко объясни логику: почему именно эти темы сегодня/на этой неделе
- Сообщи флаги темпа явно (не прячь в тексте)
- Предложи обсудить, если что-то не подходит

Если пользователь говорит:
- *«слишком много»* → убери одну задачу, предложи перенести на следующий день
- *«слишком мало»* → добавь задачу на слабую тему или незакрытый LeetCode
- *«эту тему не хочу сегодня»* → замени на следующую по приоритету
- *«иду быстрее»* → пересчитай темп, предложи приблизить дедлайн или добавить новый раздел

---

## Шаг 6 — Что НЕ делать

- Не генерировать план без чтения `🎯 Цели и сроки.md` — без дедлайнов нельзя оценить темп
- Не ставить `[x]` в банках вопросов самостоятельно
- Не переписывать `📊 Мой уровень.md` — это заполняет только пользователь
- Не создавать план на неделю вперёд, если предыдущий ещё не закрыт — сначала разбери итоги
- Не писать в дневной файл `❓ Вопросы: тема` без конкретных вопросов — это бесполезная задача
- Не генерировать Interview Questions для темы, у которой нет карточки в vault
