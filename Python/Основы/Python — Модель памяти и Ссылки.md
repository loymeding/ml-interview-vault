# Python — Модель памяти и Ссылки

> [!abstract] Суть
> В Python всё является объектом, а переменные — это лишь имена (ярлыки), ссылающиеся на эти объекты в памяти. Понимание разницы между изменением самого объекта и переназначением ссылки — ключ к написанию предсказуемого кода.

## Простыми словами

Представьте, что объекты — это дома в городе, а переменные — это адресные таблички.
*   Когда вы пишете `a = [1, 2, 3]`, вы вешаете табличку `a` на конкретный дом.
*   Если вы напишете `b = a`, вы просто вешаете вторую табличку `b` на тот же самый дом. Если вы «покрасите стены» через табличку `a`, то, взглянув через табличку `b`, вы увидите покрашенные стены, потому что дом один и тот же.
*   Неизменяемые объекты (числа, строки) — это дома, которые нельзя перекрашивать. Если вы хотите «изменить» число, Python просто строит новый дом и перевешивает туда табличку.

## Ответ

**Формальные определения и концепции**

1.  **Изменяемые (Mutable) и Неизменяемые (Immutable) типы**
    *   **Immutable**: `int`, `float`, `str`, `tuple`, `frozenset`, `bool`. После создания объект нельзя изменить. Любая «модификация» создает новый объект в памяти.
    *   **Mutable**: `list`, `dict`, `set`. Содержимое объекта можно менять на месте (in-place) без изменения его адреса в памяти.

2.  **Идентичность (is) vs Равенство (==)**
    *   **== (Равенство)**: Проверяет, одинаковые ли значения у объектов. Вызывает метод `__eq__`.
    *   **is (Идентичность)**: Проверяет, один ли это и тот же объект в памяти (сравнивает их `id()`).
    *   *Пример*: Два одинаковых списка `[1, 2]` и `[1, 2]` будут равны по `==`, но это разные объекты в памяти, поэтому `is` вернет `False`.

3.  **Копирование объектов**
    *   **Обычное присваивание (b = a)**: Создает новую ссылку на тот же объект.
    *   **Поверхностное копирование (copy.copy())**: Создает новый объект-контейнер, но вставляет в него ссылки на те же элементы, что и в оригинале.
    *   **Глубокое копирование (copy.deepcopy())**: Рекурсивно копирует не только контейнер, но и все вложенные в него объекты. Нужно, если внутри списка лежат другие изменяемые списки.

**Разбор кейсов (из файла вопросов)**

1.  **Списки как аргументы по умолчанию**
    ```python
    def add_item(item, my_list=[]): # ОПАСНО!
        my_list.append(item)
        return my_list
    ```
    *   **Проблема**: Значение по умолчанию создается **один раз** при объявлении функции. Все последующие вызовы будут использовать один и тот же объект списка в памяти. Если вызвать функцию трижды, список будет накапливать элементы.
    *   **Решение**: Использовать `my_list=None` и внутри проверять `if my_list is None: my_list = []`.

2.  **Перегрузка __eq__ в классе**
    Чтобы объекты вашего класса можно было сравнивать через `==`, нужно определить метод `__eq__`:
    ```python
    class Point:
        def __init__(self, x, y):
            self.x, self.y = x, y
        def __eq__(self, other):
            return self.x == other.x and self.y == other.y
    ```

## Типичные ошибки

*   **Изменение списка во время итерации**: Это приводит к пропуску элементов, так как индексы сдвигаются «под капотом».
*   **Использование is для сравнения чисел**: Для маленьких целых чисел (-5 до 256) в Python работает кеширование, и `is` может вернуть `True`. Но для больших чисел или строк `is` вернет `False`, даже если значения одинаковы. Всегда используйте `==` для сравнения значений.

## Каверзные вопросы

> [!question] Что произойдет, если изменить элемент кортежа (tuple), если этот элемент — список?
> Кортеж неизменяем в том смысле, что нельзя заменить ссылки в его ячейках. Но если в ячейке лежит ссылка на изменяемый объект (список), то сам список изменить можно. Адрес списка в памяти не поменяется, поэтому кортеж останется «тем же самым».

> [!question] Как работает сборщик мусора (Garbage Collector) в Python?
> Основной механизм — **подсчет ссылок** (reference counting). Как только на объект перестает ссылаться хотя бы одна переменная, память освобождается. Для обработки ситуаций, когда объекты ссылаются друг на друга по кругу (циклические ссылки), используется дополнительный алгоритм поиска циклов.
