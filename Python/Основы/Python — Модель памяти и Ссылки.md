# Python — Модель памяти и Ссылки

> [!abstract] Суть
> В Python всё является объектом, а переменные — это лишь имена (ярлыки), ссылающиеся на эти объекты в памяти. Понимание разницы между изменением самого объекта и переназначением ссылки — ключ к написанию предсказуемого кода.

> [!tip] Быстрое повторение
> 1. Переменная в Python — это имя, связанное с объектом, а не контейнер со значением.
> 2. Присваивание связывает новое имя с объектом; оно не копирует объект автоматически.
> 3. Мутация меняет существующий объект. Перепривязка имени меняет только связь имени с объектом.
> 4. Удаление имени не обязательно удаляет объект: объект исчезает, когда на него больше никто не ссылается.
> 5. Для циклических ссылок одного подсчёта ссылок недостаточно, поэтому CPython использует дополнительный сборщик мусора.

## Простыми словами

Представьте, что объекты — это дома в городе, а переменные — это адресные таблички.
*   Когда имя `a` впервые связывают со списком [1, 2, 3], оно начинает указывать на конкретный объект.
*   Если имя `b` связывают с тем же объектом, обе переменные указывают на один список. Изменение списка через `a` будет видно и через `b`.
*   Неизменяемые объекты (числа, строки) — это дома, которые нельзя перекрашивать. Если вы хотите «изменить» число, Python просто строит новый дом и перевешивает туда табличку.

## Ответ

**Формальные определения и концепции**

1.  **Изменяемые (Mutable) и Неизменяемые (Immutable) типы**
    *   **Immutable**: `int`, `float`, `str`, `tuple`, `frozenset`, `bool`. После создания объект нельзя изменить. Любая «модификация» создает новый объект в памяти.
    *   **Mutable**: `list`, `dict`, `set`. Содержимое объекта можно менять на месте (in-place) без изменения его адреса в памяти.

2.  **Переприсваивание не является мутацией**
    Если имя `a` сначала связывает с числом 3, а затем с числом 4, объект 3 не изменяется. Мутация — это изменение самого объекта, например вызов `lst.append(4)` для списка.

~~~python
a = [1, 2]
b = a
a.append(3)  # мутация объекта, b тоже увидит [1, 2, 3]

x = 3
x = 4        # перепривязка имени, объект 3 не изменился
~~~

3.  **Идентичность (is) и равенство значений**
    *   **Сравнение по значению**: проверяет, одинаковые ли значения у объектов. Для этого используется метод `__eq__`.
    *   **is (Идентичность)**: Проверяет, один ли это и тот же объект в памяти (сравнивает их `id()`).
    *   *Пример*: два одинаковых списка имеют равные значения, но это разные объекты в памяти, поэтому проверка идентичности через `is` вернёт `False`.

4.  **Копирование объектов**
    *   **Обычное присваивание**: создаёт новую ссылку на тот же объект.
    *   **Поверхностное копирование (copy.copy())**: Создает новый объект-контейнер, но вставляет в него ссылки на те же элементы, что и в оригинале.
    *   **Глубокое копирование (copy.deepcopy())**: Рекурсивно копирует не только контейнер, но и все вложенные в него объекты. Нужно, если внутри списка лежат другие изменяемые списки.

**Разбор кейсов (из файла вопросов)**

1.  **Списки как аргументы по умолчанию**
~~~python
def add_item(item, my_list=[]): # ОПАСНО!
    my_list.append(item)
    return my_list
~~~
    *   **Проблема**: Значение по умолчанию создается **один раз** при объявлении функции. Все последующие вызовы будут использовать один и тот же объект списка в памяти. Если вызвать функцию трижды, список будет накапливать элементы.
    *   **Решение**: использовать значение «по умолчанию отсутствует», а внутри функции создавать новый список только при необходимости.

2.  **Перегрузка __eq__ в классе**
    Чтобы объекты вашего класса можно было сравнивать по значению, нужно определить специальный метод `__eq__`:
~~~python
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __eq__(self, other):
        if not isinstance(other, Point):
            return NotImplemented
        return self.x == other.x and self.y == other.y
~~~
    Если объект должен быть ключом словаря или элементом `set`, нужно также корректно определить `__hash__` и не менять поля, участвующие в хэше. Если класс переопределяет `__eq__`, Python по умолчанию делает его unhashable, чтобы не сломать инварианты hash table.

## Передача аргументов: не «по ссылке» и не «по значению»

В Python функция получает ссылку на тот же объект, который был передан вызывающим кодом. Поэтому результат зависит от того, изменяемый объект или нет.

~~~python
def add_item(items):
    items.append("new")


values = ["old"]
add_item(values)
print(values)  # ["old", "new"]
~~~

Функция изменила общий список. С числом ситуация другая:

~~~python
def increase(value):
    value += 1


number = 10
increase(number)
print(number)  # 10
~~~

Внутри функции появилось новое локальное связывание имени value. Исходное число не изменилось, потому что int неизменяем.

## del, сборка мусора и жизненный цикл объекта

Оператор del удаляет имя, элемент контейнера или атрибут. Он не означает «немедленно освободи память».

~~~python
first = []
second = first

del first
print(second)  # объект всё ещё доступен

del second
~~~

После удаления второго имени объект становится недостижимым. В CPython обычные объекты освобождаются, когда счётчик ссылок становится нулём. Точный момент освобождения ресурсов не следует использовать как замену явному закрытию файла или соединения.

Для файлов, сокетов и транзакций используйте контекстные менеджеры, а не надежду на момент работы GC.

## Циклические ссылки

Цикл возникает, когда объекты прямо или косвенно ссылаются друг на друга:

~~~python
first = []
second = []

first.append(second)
second.append(first)

del first
del second
~~~

После удаления внешних имён ссылки внутри цикла сохраняются. Подсчёт ссылок не видит, что цикл больше недостижим. Дополнительный cyclic GC периодически ищет такие группы объектов и освобождает их.

Циклы сами по себе не всегда ошибка, но они усложняют жизненный цикл и могут задержать освобождение памяти. Для ссылок на владельца иногда используют weakref, которая не увеличивает счётчик сильных ссылок.

## Как диагностировать неожиданное поведение

~~~python
import sys


values = []
alias = values

print(id(values))
print(id(alias))
print(values is alias)
print(sys.getrefcount(values))
~~~

getrefcount временно добавляет ссылку из-за передачи аргумента, поэтому его значение приблизительное. Для поиска утечек памяти лучше использовать tracemalloc и профилировщики, а не печатать id в production.

## Вопросы для собеседования

> [!question] Что происходит при переназначении неизменяемого объекта?
> Старый объект не меняется. Имя начинает ссылаться на другой объект, а прежний может быть освобождён, если на него больше нет ссылок.

> [!question] Почему два имени иногда видят одну мутацию?
> Потому что они указывают на один и тот же изменяемый объект. Присваивание второго имени не создаёт копию.

> [!question] Почему del не всегда освобождает память?
> del убирает конкретную ссылку. Если остались другие имена, элементы контейнеров или ссылки внутри цикла, объект продолжает жить.

> [!question] Почему tuple иногда содержит изменяемые данные?
> Сам кортеж не позволяет заменить ссылки в своих позициях, но объект, на который указывает одна из ссылок, например список, может изменяться.

> [!question] Когда нужен deepcopy?
> Когда требуется независимая копия вложенных изменяемых объектов. Для больших графов объектов deepcopy может быть дорогим и копировать больше, чем действительно нужно.

## Типичные ошибки

*   **Изменение списка во время итерации**: Это приводит к пропуску элементов, так как индексы сдвигаются «под капотом».
*   **Использование is для сравнения чисел**: для маленьких целых чисел (-5 до 256) в Python работает кеширование, и `is` может вернуть `True`. Но для больших чисел или строк `is` вернёт `False`, даже если значения одинаковы. Для сравнения значений используйте оператор равенства.

## Каверзные вопросы

> [!question] Что произойдет, если изменить элемент кортежа (tuple), если этот элемент — список?
> Кортеж неизменяем в том смысле, что нельзя заменить ссылки в его ячейках. Но если в ячейке лежит ссылка на изменяемый объект (список), то сам список изменить можно. Адрес списка в памяти не поменяется, поэтому кортеж останется «тем же самым».

> [!question] Как работает сборщик мусора (Garbage Collector) в Python?
> Основной механизм — **подсчет ссылок** (reference counting). Как только на объект перестает ссылаться хотя бы одна переменная, память освобождается. Для обработки ситуаций, когда объекты ссылаются друг на друга по кругу (циклические ссылки), используется дополнительный алгоритм поиска циклов.
