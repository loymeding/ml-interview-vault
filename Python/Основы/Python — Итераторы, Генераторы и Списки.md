# Python — итераторы, генераторы и списки

> [!abstract] Главная идея
> Список хранит все элементы сразу. Итератор хранит текущее положение и выдаёт элементы по одному. Генератор — самый удобный способ написать итератор: мы описываем обычный цикл с ключевым словом yield, а Python сам сохраняет его состояние между вызовами.

> [!tip] Быстрое повторение перед собеседованием
> - **Iterable (итерируемый объект)** можно передать в `iter()`, **iterator (итератор)** можно передать в `next()`.
> - `for` сам получает итератор и повторяет `next()` до `StopIteration`.
> - Генераторная функция начинает выполняться при первом `next()`, а `yield` временно сохраняет её состояние.
> - Генератор обычно экономит память, но одноразовый: для второго прохода его нужно создать заново.
> - Список выбираем, когда нужны индексы, длина, повторный проход или случайный доступ; генератор — когда важна потоковая обработка.

Эти понятия часто смешивают, потому что список, итератор и генератор можно передать в один и тот же цикл for. Но внутри они устроены по-разному. Сначала разберём одну и ту же последовательность тремя способами, а затем свяжем это с практикой.

## 1. Четыре понятия, которые нужно различать

| Понятие | Что это | Хранит все элементы | Можно вызвать next |
|---|---|---:|---:|
| Iterable, итерируемый объект | Объект, из которого можно получить итератор | Не обязательно | Не обязательно |
| Iterator, итератор | Объект с текущей позицией и методом next | Обычно нет | Да |
| Generator, генератор | Особый итератор, созданный через yield | Обычно нет | Да |
| List, список | Готовый массив элементов | Да | Нет напрямую |

Главная цепочка:

~~~text
iterable -- iter() --> iterator -- next() --> очередной элемент
~~~

Генератор уже является итератором, а список обычно является только итерируемым объектом.

## 2. Список и его итератор

Начнём со списка:

~~~python
numbers = [10, 20, 30]
~~~

Все три числа уже находятся в памяти. Из списка можно получить отдельный объект обхода:

~~~python
numbers = [10, 20, 30]
iterator = iter(numbers)

print(next(iterator))  # 10
print(next(iterator))  # 20
print(next(iterator))  # 30
print(next(iterator))  # StopIteration
~~~

После первого next итератор стоит перед числом 20. После второго — перед числом 30. После третьего элементов больше нет, поэтому следующий вызов сообщает об окончании через исключение StopIteration.

Список не изменился. Изменилось состояние объекта iterator:

~~~text
numbers:  [10, 20, 30]  — все элементы лежат в памяти
iterator:                 позиция 0
next(iterator) → 10       позиция 1
next(iterator) → 20       позиция 2
next(iterator) → 30       позиция 3
next(iterator) → StopIteration
~~~

Можно создать два независимых итератора одного списка:

~~~python
numbers = [10, 20, 30]
first = iter(numbers)
second = iter(numbers)

print(next(first))   # 10
print(next(first))   # 20
print(next(second))  # снова 10
~~~

У каждого итератора собственная текущая позиция.

## 3. Как цикл for использует итератор

Когда мы пишем:

~~~python
for number in numbers:
    print(number)
~~~

Python концептуально делает примерно следующее:

~~~python
iterator = iter(numbers)

while True:
    try:
        number = next(iterator)
    except StopIteration:
        break

    print(number)
~~~

Именно поэтому в for можно передавать не только списки, но и строки, словари, файлы, range, генераторы и свои классы.

## 4. Что такое iterable

Итерируемый объект — это объект, из которого можно получить итератор с помощью iter().

Примеры:

~~~python
iter([1, 2, 3])
iter("hello")
iter({"a": 1, "b": 2})
iter(open("data.txt"))
iter(range(10))
~~~

Обычно iterable реализует метод __iter__, который возвращает новый итератор.

~~~python
numbers = [10, 20, 30]
iterator = iter(numbers)

print(iter(numbers) is numbers)    # False
print(iter(iterator) is iterator)  # True
~~~

Для списка iter(numbers) создаёт отдельный объект обхода. Для самого итератора iter(iterator) возвращает его же, потому что итератор уже хранит текущую позицию.

## 5. Что такое iterator

Итератор должен поддерживать два метода:

1. __iter__() — вернуть сам итератор;
2. __next__() — вернуть следующий элемент или выбросить StopIteration.

Напишем итератор вручную. Он будет выдавать числа от 1 до заданного максимума.

~~~python
class CountUpTo:
    def __init__(self, limit):
        self.limit = limit
        self.current = 1

    def __iter__(self):
        return self

    def __next__(self):
        if self.current > self.limit:
            raise StopIteration

        value = self.current
        self.current += 1
        return value


counter = CountUpTo(3)
print(next(counter))  # 1
print(next(counter))  # 2
print(next(counter))  # 3
~~~

Здесь состояние явно хранится в self.current. После каждого вызова __next__ счётчик увеличивается.

Такой объект можно передать в for:

~~~python
for number in CountUpTo(3):
    print(number)
~~~

Ручной класс полезен, когда у обхода сложное состояние, несколько режимов или особая логика остановки. Но для простого последовательного обхода он многословен. Обычно вместо него пишут генератор.

## 6. Что такое генератор

Генератор — это итератор, который Python создаёт автоматически из функции с yield.

~~~python
def count_up_to(limit):
    current = 1

    while current <= limit:
        yield current
        current += 1


counter = count_up_to(3)
print(next(counter))  # 1
print(next(counter))  # 2
print(next(counter))  # 3
~~~

Ключевые отличия:

- вызов count_up_to(3) не выполняет тело функции до конца;
- yield возвращает значение и ставит выполнение на паузу;
- следующий next продолжает функцию с места после yield;
- локальные переменные и положение в цикле сохраняются автоматически.

Пошагово:

~~~text
создали counter  → тело функции ещё не выполнялось
первый next()   → current = 1, yield 1, пауза
второй next()   → current = 2, yield 2, пауза
третий next()   → current = 3, yield 3, пауза
четвёртый next  → условие завершено, StopIteration
~~~

Именно поэтому генератор — удобный способ создать итератор без ручного хранения current и реализации __next__.

## 7. Сравнение списка и генератора на одном примере

### Список

~~~python
def make_list(n):
    result = []

    for i in range(n):
        result.append(i * i)

    return result


values = make_list(1_000_000)
~~~

Сначала вычисляются и сохраняются все миллион значений. Только после этого функция возвращает результат.

### Генератор

~~~python
def make_generator(n):
    for i in range(n):
        yield i * i


values = make_generator(1_000_000)
~~~

Здесь миллион значений не вычисляется сразу. При создании values появляется небольшой объект-генератор. Каждое число вычисляется только в момент запроса:

~~~python
print(next(values))  # вычислилось только 0
print(next(values))  # вычислилось только 1
~~~

Если остановиться после двух элементов, остальные 999 998 значений вообще не будут вычислены.

| Свойство | Список | Генератор |
|---|---|---|
| Момент вычисления | Сразу | При запросе очередного элемента |
| Память | Все элементы | Текущее состояние |
| Доступ по индексу | Да | Нет |
| Повторный проход | Да | Нет, если не создать заново |
| Бесконечный поток | Обычно невозможен | Возможен |
| Удобство просмотра | Можно посмотреть весь результат | Нужно обходить или материализовать |

## 8. yield и return

return завершает функцию и возвращает одно итоговое значение:

~~~python
def get_value():
    return 10


result = get_value()
print(result)  # 10
~~~

yield возвращает очередное значение, но оставляет функцию в состоянии паузы:

~~~python
def get_values():
    yield 10
    yield 20
    yield 30
~~~

После выдачи 30 следующий вызов приведёт к StopIteration. Если внутри генератора написать return, это означает завершение генератора.

## 9. Генераторное выражение

Для простых случаев генератор можно создать без отдельной функции:

~~~python
squares = (number * number for number in range(10))
~~~

Круглые скобки создают генератор, квадратные — список:

~~~python
lazy_values = (x * 2 for x in range(1_000_000))
ready_values = [x * 2 for x in range(1_000_000)]
~~~

Если результат сразу передаётся функции, которая умеет итерироваться, промежуточный список часто не нужен:

~~~python
total = sum(x * x for x in range(1_000_000))
~~~

## 10. Где генераторы применяются в production

### Большой файл

Плохой вариант загружает всё в память:

~~~python
with open("events.log", encoding="utf-8") as file:
    lines = file.readlines()

for line in lines:
    process(line)
~~~

Лучший вариант обрабатывает строки постепенно:

~~~python
with open("events.log", encoding="utf-8") as file:
    for line in file:
        process(line)
~~~

Файл сам является итерируемым объектом.

### Пагинация API

~~~python
def iter_pages(fetch_page):
    cursor = None

    while True:
        page = fetch_page(cursor)

        for item in page["items"]:
            yield item

        cursor = page.get("next_cursor")
        if cursor is None:
            break
~~~

Так можно обработать миллионы записей, не загружая все страницы сразу.

### Потоковая обработка

~~~python
def read_purchase_events(events):
    for event in events:
        if event["type"] == "purchase":
            yield event


large_purchases = (
    event for event in read_purchase_events(events)
    if event["amount"] > 10_000
)
~~~

До момента обхода данные не фильтруются. Вычисления запускаются, когда следующий этап просит очередной элемент.

## 11. Генератор выполняется лениво

~~~python
def numbers():
    print("Начало работы")
    yield 1
    print("Продолжение работы")
    yield 2


generator = numbers()
print("Генератор создан")
print(next(generator))
print(next(generator))
~~~

Вывод:

~~~text
Генератор создан
Начало работы
1
Продолжение работы
2
~~~

Тело функции начинает работать только во время первого next, for, list или другой операции обхода.

## 12. Генератор можно обойти только один раз

~~~python
generator = (x * 2 for x in range(3))

print(list(generator))  # [0, 2, 4]
print(list(generator))  # []
~~~

После первого обхода генератор исчерпан. Если нужен повторный проход, создайте его заново или сохраните результат в список.

Список можно обходить много раз:

~~~python
values = [0, 2, 4]
print(list(values))
print(list(values))
~~~

## 13. yield from

yield from позволяет передавать элементы другого итерируемого объекта:

~~~python
def all_numbers():
    yield from range(3)
    yield from range(10, 13)


print(list(all_numbers()))  # [0, 1, 2, 10, 11, 12]
~~~

Это удобно для объединения нескольких источников или вложенных генераторов.

## 14. Когда список лучше генератора

Список нужен, когда:

- необходим доступ по индексу;
- требуется несколько проходов;
- нужно отсортировать данные;
- нужно узнать длину;
- результат небольшой;
- важно посмотреть весь промежуточный результат.

Генератор нужен, когда:

- данных много;
- результат приходит частями;
- вычисление дорогое;
- часть элементов может не понадобиться;
- источник является бесконечным или потоковым.

Практическое правило:

> Список — готовый набор данных. Итератор — механизм последовательного обхода. Генератор — удобный ленивый итератор, который выдаёт следующий элемент по запросу.

## 15. Сложность операций со списком

Python-список реализован как динамический массив ссылок на объекты.

| Операция | Средняя сложность | Причина |
|---|---:|---|
| values[i] | O(1) | Адрес вычисляется по индексу |
| append(x) | O(1) амортизированно | Обычно есть запас места |
| pop() с конца | O(1) | Не нужно сдвигать элементы |
| insert(0, x) | O(n) | Элементы сдвигаются вправо |
| pop(0) | O(n) | Элементы сдвигаются влево |
| x in values | O(n) | Последовательный поиск |
| values[a:b] | O(k) | Создаётся новый список |
| сортировка | O(n log n) | Сортировка сравнениями |

Если нужно часто добавлять и удалять элементы с начала, используйте collections.deque.

## 16. Список, NumPy и pandas

Список может содержать объекты разных типов:

~~~python
values = [1, 2.5, "text", None]
~~~

NumPy-массив обычно хранит значения одного типа в компактном блоке памяти:

~~~python
import numpy as np

values = np.array([1, 2, 3, 4])
result = values * 2
~~~

NumPy быстрее на массовых числовых операциях, потому что вычисления выполняются в оптимизированном низкоуровневом коде. Генератор экономит память, но сам по себе не делает Python-вычисления быстрыми.

При работе с DataFrame сначала ищите векторную операцию:

~~~python
df["amount_2x"] = df["amount"] * 2
~~~

Если цикл нужен:

- iterrows() возвращает каждую строку как Series и обычно медленный;
- itertuples() обычно заметно быстрее;
- векторизация чаще всего быстрее обоих вариантов.

## 17. Типичные ошибки

### Вызвать next у списка

~~~python
values = [1, 2, 3]
next(values)  # TypeError
~~~

Нужно сначала получить iterator через iter(values).

### Случайно исчерпать генератор

Если один участок программы полностью обошёл генератор, второй получит пустой результат.

### Без причины преобразовать большой генератор в список

list(very_large_generator()) загружает все элементы в память. Это нормально, только если весь результат действительно нужен одновременно.

### Ожидать, что генератор всегда быстрее

Генератор экономит память и позволяет начать обработку раньше, но каждый элемент проходит через Python-механику next. Для небольшого набора список может быть быстрее.

### Забыть о побочных эффектах

У генератора сетевой запрос, запись в файл или изменение состояния происходят во время обхода, а не во время создания объекта.

## 18. Вопросы для собеседования

> [!question] Генератор — iterable или iterator?
> И то и другое. У него есть __iter__ и __next__, поэтому его можно передать в for и вызвать next.

> [!question] Любой iterable является iterator?
> Нет. Список — iterable, но не iterator. Из списка сначала получают iterator через iter.

> [!question] Выполняется ли тело генератора при создании?
> Нет. Оно начинает выполняться при первом next или другой операции обхода.

> [!question] Почему for не выбрасывает StopIteration наружу?
> Цикл перехватывает это исключение и использует его как сигнал завершения.

> [!question] Всегда ли генератор экономит память?
> Нет. Если внутри генератора сначала построить большой список, память всё равно будет потрачена.
