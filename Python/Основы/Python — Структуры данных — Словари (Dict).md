# Python — структуры данных: словари (dict)

> [!abstract] Быстрое повторение
> Словарь — отображение «ключ → значение», реализованное в CPython на основе хеш-таблицы с открытой адресацией. Поиск, вставка и удаление в среднем занимают O(1), но в худшем случае могут занять O(n). Ключ должен быть hashable: его хеш и равенство не должны меняться, пока ключ находится в словаре.

Словарь — одна из самых часто проверяемых структур на Python-интервью. Важно не только помнить, что доступ быстрый, но и понимать, почему это так, когда появляются коллизии, какие объекты можно использовать как ключи и какие методы делают код надёжнее.

## 1. Как думать о словаре

~~~python
prices = {
    "apple": 120,
    "bread": 80,
}
~~~

Словарь хранит пары:

~~~text
ключ "apple" → значение 120
ключ "bread" → значение 80
~~~

Ключ используется для быстрого поиска, значение может быть почти любым объектом.

~~~python
prices["apple"]       # получить значение
prices["milk"] = 150  # добавить или обновить
del prices["bread"]   # удалить
~~~

Словарь не ищет ключ последовательным просмотром всех элементов, как список. Сначала он вычисляет hash ключа и по нему находит предполагаемую позицию.

## 2. Как работает хеш-таблица

Упрощённая схема:

1. Python вызывает hash(key).
2. Полученное число преобразуется в индекс внутренней таблицы.
3. В найденной позиции проверяется сам ключ.
4. Если ключ равен искомому, возвращается значение.
5. Если позиция занята другим ключом, используется последовательность проб — поиск другой позиции.

Важно, что одного совпадения хешей недостаточно для равенства ключей. После совпадения хешей Python дополнительно сравнивает ключи через равенство.

В CPython используется открытая адресация: записи находятся внутри самой таблицы, а не в отдельных связанных списках. Конкретная реализация может меняться между версиями Python, поэтому на интервью достаточно объяснить принцип, а не воспроизводить внутреннюю формулу пробирования.

Начиная с Python 3.7 порядок добавления ключей является гарантией языка. Это не означает сортировку: ключи возвращаются в порядке вставки.

## 3. Сложность операций

| Операция | Средний случай | Худший случай |
|---|---:|---:|
| Получить значение по ключу | O(1) | O(n) |
| Добавить или обновить ключ | O(1) | O(n) |
| Удалить ключ | O(1) | O(n) |
| Проверить наличие ключа | O(1) | O(n) |
| Обойти все элементы | O(n) | O(n) |

Средняя сложность O(1) означает, что размер словаря обычно почти не влияет на время одного поиска. Это не означает «всегда ровно одна операция» и не гарантирует постоянное время при плохих хешах или расширении таблицы.

Иногда вставка занимает больше времени, потому что словарю нужно увеличить внутреннюю таблицу и переразместить записи. Для отдельной операции это дорого, но в серии вставок средняя стоимость остаётся амортизированно O(1).

## 4. Почему возможен худший случай O(n)

Худший случай возникает, если много ключей попадает в одни и те же позиции. Тогда словарь вынужден проверять длинную последовательность кандидатов.

Это может произойти из-за:

- плохой реализации __hash__;
- большого числа коллизий;
- искусственно подготовленных входных данных;
- слишком маленькой внутренней таблицы до её расширения.

При нормальных встроенных типах Python старается распределять ключи равномерно. Для строк и некоторых других типов используются дополнительные меры защиты от атак с предсказуемыми коллизиями.

## 5. Что такое коллизия

Коллизия — ситуация, когда:

- два разных ключа имеют одинаковый хеш;
- или разные хеши после преобразования попали в один слот.

Пример на уровне идеи:

~~~text
hash("cat") → 17
hash("dog") → 17
~~~

Словарь не теряет один из ключей. Он ищет другое место и при чтении проверяет не только хеш, но и равенство самих ключей.

Основные методы борьбы с коллизиями в хеш-таблицах:

- открытая адресация и пробирование;
- цепочки, когда в одной позиции хранится список записей;
- изменение размера таблицы;
- более равномерная хеш-функция.

В CPython для dict используется открытая адресация.

## 6. Каким должен быть ключ

Ключ должен быть hashable — хешируемым объектом. Это означает:

1. у него есть стабильный хеш;
2. он корректно сравнивается с другими ключами;
3. его состояние, влияющее на hash и equality, не меняется во время хранения в словаре.

Обычно подходят:

~~~python
data = {
    10: "number",
    "user_id": "string",
    (10, 20): "tuple",
    frozenset({"a", "b"}): "immutable set",
}
~~~

Список, словарь и обычное множество ключами быть не могут:

~~~python
data = {
    [1, 2]: "value"  # TypeError: unhashable type: list
}
~~~

Кортеж подходит только тогда, когда все его элементы тоже хешируемы:

~~~python
good = {(1, 2): "ok"}
bad = {(1, [2]): "error"}  # внутри есть изменяемый список
~~~

## 7. Связь hash и equality

Если два объекта равны, их хеши обязаны совпадать:

~~~text
a == b  →  hash(a) == hash(b)
~~~

Обратное неверно: одинаковый хеш не означает, что объекты равны. Это и есть одна из причин коллизий.

Пример пользовательского ключа:

~~~python
class UserKey:
    def __init__(self, user_id):
        self.user_id = user_id

    def __eq__(self, other):
        if not isinstance(other, UserKey):
            return NotImplemented
        return self.user_id == other.user_id

    def __hash__(self):
        return hash(self.user_id)
~~~

После помещения такого объекта в словарь нельзя менять user_id. Если хеш изменится, словарь может не найти уже существующую запись.

Если класс переопределяет __eq__, Python обычно делает его нехешируемым, пока разработчик явно не определит безопасный __hash__. Это защищает от случайного нарушения инвариантов.

## 8. Практические методы dict

### Безопасное чтение

~~~python
value = prices.get("milk")
value_with_default = prices.get("milk", 0)
~~~

Обращение через квадратные скобки выбрасывает KeyError, если ключ отсутствует. get возвращает None или заданное значение по умолчанию.

~~~python
prices["milk"]       # KeyError, если ключа нет
prices.get("milk")   # None, если ключа нет
~~~

### Проверка наличия

~~~python
if "apple" in prices:
    print(prices["apple"])
~~~

Проверять наличие через in лучше, чем ловить KeyError без необходимости.

### setdefault

~~~python
groups = {}
groups.setdefault("ml", []).append("Alice")
~~~

setdefault возвращает существующее значение или создаёт значение по умолчанию. Для частотных групп часто понятнее использовать defaultdict.

### defaultdict

~~~python
from collections import defaultdict

groups = defaultdict(list)
groups["ml"].append("Alice")
groups["ml"].append("Bob")
~~~

### Counter

~~~python
from collections import Counter

counts = Counter(["cat", "dog", "cat"])
print(counts["cat"])  # 2
print(counts.most_common(1))
~~~

Counter удобен для подсчёта частот и читается лучше, чем ручное увеличение значения в словаре.

## 9. Представления keys, values и items

Методы keys, values и items возвращают динамические представления, а не обязательно отдельные списки.

~~~python
data = {"a": 1, "b": 2}
items = data.items()

data["c"] = 3
print(list(items))  # представление увидит изменение
~~~

Нельзя безопасно изменять размер словаря во время обхода:

~~~python
for key in data:
    if key.startswith("a"):
        del data[key]  # RuntimeError
~~~

Если нужна фильтрация, создайте отдельный словарь:

~~~python
filtered = {
    key: value
    for key, value in data.items()
    if value > 1
}
~~~

## 10. Типовой паттерн: подсчёт частот

Плохой вариант:

~~~python
counts = {}

for label in labels:
    counts[label] = labels.count(label)
~~~

Здесь count каждый раз проходит по всему списку, поэтому общая сложность может стать O(n²).

Лучше:

~~~python
counts = {}

for label in labels:
    counts[label] = counts.get(label, 0) + 1
~~~

Или:

~~~python
from collections import Counter

counts = Counter(labels)
~~~

## 11. Когда dict не лучший выбор

Используйте список, если:

- нужен доступ по позиции;
- важны дубликаты;
- нужен последовательный порядок элементов без ключей.

Используйте set, если:

- нужны только уникальные значения;
- часто проверяется принадлежность;
- значение для каждого элемента не нужно.

Используйте defaultdict или Counter, если задача связана с группировкой или частотами.

Используйте OrderedDict только для специальных операций с порядком, например move_to_end. Для обычного сохранения порядка достаточно обычного dict.

## 12. Типичные ошибки

- Использовать список как ключ.
- Забывать, что кортеж с изменяемым элементом тоже нехешируем.
- Менять поля пользовательского ключа после добавления в словарь.
- Использовать квадратные скобки, когда отсутствие ключа является нормальной ситуацией.
- Изменять размер словаря во время обхода.
- Делать labels.count внутри цикла и получать O(n²).
- Считать, что порядок словаря означает сортировку.
- Объяснять dict как обычный массив без проверки equality после совпадения хеша.

## 13. Вопросы для собеседования

> [!question] Почему dict в среднем работает за O(1)?
> Хеш ключа сразу указывает на небольшую область таблицы, поэтому не нужно просматривать все записи. После этого Python проверяет equality ключа.

> [!question] Почему худший случай O(n)?
> При большом числе коллизий приходится проверять длинную последовательность кандидатов.

> [!question] Почему ключ должен быть неизменяемым?
> Словарь использует его хеш для поиска. Если хеш изменится после вставки, запись окажется в старой позиции, а новый поиск будет искать её уже в другом месте.

> [!question] Почему два ключа с одинаковым хешем не считаются одним ключом?
> Хеш — только быстрый способ найти кандидата. Затем сравниваются сами ключи. Одинаковый хеш не означает equality.

> [!question] Сохраняет ли dict порядок?
> Да, начиная с Python 3.7 порядок вставки является гарантией языка. Это не сортировка по ключу.

> [!question] Чем dict отличается от set?
> set хранит уникальные ключи без связанных с ними значений. dict хранит отображение ключей в значения.
