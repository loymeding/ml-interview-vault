# Python — Параллелизм и Конкурентность

> [!abstract] Суть
> Выбор между многопоточностью (Threading) и многопроцессорностью (Multiprocessing) зависит от типа задачи: нужно ли нам ждать внешние ресурсы (I/O) или выполнять тяжелые вычисления (CPU). В Python этот выбор осложняется наличием GIL.

## Простыми словами

*   **Потоки (Threads)** — это как повара на одной кухне. У них общие кастрюли, холодильник и продукты (общая память). Это удобно, чтобы быстро обмениваться данными, но если на кухне всего одна плита (**GIL**), то готовить одновременно они не смогут — будут постоянно передавать друг другу черпак. Это отлично работает, когда один повар ждет, пока закипит чайник (сетевой запрос), и в это время другой может резать овощи.
*   **Процессы (Processes)** — это как несколько разных кафе. У каждого своя кухня, свои продукты и своя плита. Они работают абсолютно независимо и одновременно. Если вам нужно приготовить 100 обедов очень быстро, лучше открыть 4 кафе, чем запихивать 4 поваров на одну маленькую кухню. Но передавать продукты из одного кафе в другое гораздо сложнее и дороже.

## Ответ

**Формальные определения и различия**

1.  **Потоки (Threading)**
    *   **Сущность**: Наименьшая единица исполнения в рамках одного процесса.
    *   **Память**: Все потоки одного процесса разделяют общее адресное пространство.
    *   **GIL (Global Interpreter Lock)**: Глобальная блокировка интерпретатора. В стандартном Python (CPython) GIL позволяет только одному потоку исполнять байт-код в один момент времени.
    *   **Когда использовать**: I/O-bound задачи (запросы в сеть, чтение файлов, работа с БД). Пока один поток ждет ответа от сервера, Python переключается на другой.

2.  **Процессы (Multiprocessing)**
    *   **Сущность**: Изолированная программа со своим набором ресурсов.
    *   **Память**: У каждого процесса своя область памяти. Общение между процессами (IPC) требует сериализации данных (pickle).
    *   **Параллелизм**: Процессы могут работать на разных ядрах процессора одновременно, обходя ограничения GIL.
    *   **Когда использовать**: CPU-bound задачи (тяжелые математические расчеты, обработка изображений, обучение моделей).

**Сравнительная таблица**

| Характеристика | Потоки (Threading) | Процессы (Multiprocessing) |
| :--- | :--- | :--- |
| **Память** | Общая (Shared) | Изолированная (Separate) |
| **Параллелизм** | Псевдо-параллелизм (из-за GIL) | Настоящий параллелизм |
| **Затраты на создание** | Низкие | Высокие |
| **Сложность обмена данными** | Низкая (общие переменные) | Высокая (очереди, каналы, Pipe) |
| **Безопасность** | Риск Race Conditions (состояние гонки) | Безопасно для данных |

**Разбор кейсов (из файла вопросов)**

*   **Мультипроцессинг vs Мультитрейдинг в Data Science**: В анализе данных чаще используется Multiprocessing. Например, библиотеки scikit-learn (параметр `n_jobs`) или multiprocessing позволяют распараллелить обучение моделей или обработку строк датасета на все ядра процессора. Потоки в DS полезны разве что при парсинге данных из интернета.

## Типичные ошибки

*   **Использование потоков для расчетов**: Ожидание ускорения вычислений в потоках в Python — классическая ошибка новичка. Из-за GIL код будет работать даже медленнее, чем в один поток, из-за затрат на переключение контекста.
*   **Race Conditions**: Забывать про Lock (мьютексы) при работе с общими данными в потоках.

## Каверзные вопросы

> [!question] Поможет ли Multiprocessing, если у меня одноядерный процессор?
> Практически нет. На одном ядре даже процессы будут выполняться по очереди (вытесняющая многозадачность ОС), и вы только потратите ресурсы на создание процессов и копирование памяти.

> [!question] Как GIL понимает, когда пора переключить поток?
> Python переключает потоки либо когда поток уходит в ожидание (I/O), либо по истечении фиксированного интервала времени (по умолчанию 5 миллисекунд в Python 3.2+). Это называется "cooperative multitasking".
