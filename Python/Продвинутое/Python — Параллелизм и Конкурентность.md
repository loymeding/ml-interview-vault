# Python — параллелизм и конкурентность

> [!abstract] Быстрое повторение
> **Конкурентность** означает, что несколько задач продвигаются вперемешку. **Параллелизм** означает, что задачи действительно выполняются одновременно. Для ожидания сети подходят asyncio или потоки, для тяжёлых вычислений на Python — процессы, а для числовых библиотек часто достаточно NumPy, PyTorch или другого кода, который работает вне интерпретатора.

> [!tip] Аналогия
> Один официант, который принимает заказ одного стола, пока кухня готовит другой, — конкурентное выполнение. Несколько официантов, работающих одновременно, — параллелизм. В Python потоки хорошо перекрывают ожидание, но GIL ограничивает одновременное выполнение чистого Python-кода.

## 1. Сначала определите тип нагрузки

### I/O-bound

Программа большую часть времени ждёт внешний ресурс:

- HTTP-запрос;
- базу данных;
- файл;
- очередь сообщений;
- ответ LLM.

Здесь конкурентность уменьшает простой процессора.

### CPU-bound

Программа почти всё время считает:

- сложный Python-цикл;
- обработку изображений;
- преобразование большого массива;
- расчёт признаков;
- перебор вариантов.

Здесь нужен настоящий параллелизм или оптимизированная библиотека.

## 2. Потоки

Потоки работают внутри одного процесса и имеют общую память. Если один поток ждёт сеть, другой может выполнять работу.

~~~python
from concurrent.futures import ThreadPoolExecutor


def fetch(url):
    # синхронный HTTP-вызов
    return download(url)


with ThreadPoolExecutor(max_workers=10) as pool:
    results = list(pool.map(fetch, urls))
~~~

Плюсы:

- простой обмен данными;
- подходят для синхронных библиотек;
- дешевле процессов;
- хорошо перекрывают I/O.

Минусы:

- общая память создаёт риск гонок;
- чистый Python CPU-код ограничен GIL;
- большое число потоков увеличивает переключения и расход памяти.

## 3. Процессы

Процесс имеет собственный интерпретатор и собственную память. Процессы могут выполняться на разных ядрах и обходят GIL.

~~~python
from concurrent.futures import ProcessPoolExecutor


def calculate_features(row):
    return expensive_python_calculation(row)


if __name__ == "__main__":
    with ProcessPoolExecutor() as pool:
        results = list(pool.map(calculate_features, rows))
~~~

На Windows проверка main обязательна, потому что новый процесс запускает модуль заново.

Цена процессов:

- аргументы и результаты сериализуются;
- передача больших DataFrame может быть дорогой;
- запуск тяжелее;
- общую память приходится организовывать отдельно.

## 4. Asyncio

asyncio обычно использует один поток и event loop. Корутина добровольно отдаёт управление в точке await, пока ждёт неблокирующую операцию.

~~~python
import asyncio


async def fetch(url, client):
    response = await client.get(url)
    return response


async def main(urls, client):
    tasks = [fetch(url, client) for url in urls]
    return await asyncio.gather(*tasks)
~~~

asyncio хорошо подходит для большого числа сетевых операций и долгоживущих соединений.

Внутри async-функции нельзя вызывать блокирующий time.sleep, requests.get или тяжёлый Python-цикл. Они остановят event loop и задержат все остальные задачи.

Если синхронную библиотеку заменить нельзя, блокирующий вызов можно вынести в поток через asyncio.to_thread.

## 5. Ограничение конкуренции

Запустить тысячу запросов одновременно обычно опасно: можно исчерпать память или превысить лимит сервиса.

~~~python
import asyncio


limit = asyncio.Semaphore(20)


async def limited_fetch(url, client):
    async with limit:
        async with asyncio.timeout(5):
            return await client.get(url)
~~~

В production также нужны таймауты, повторные попытки с backoff, обработка отмены и понятное журналирование.

## 6. Общая память и гонки

Если два потока меняют одну переменную, результат может зависеть от порядка переключения.

~~~python
import threading


counter = 0
lock = threading.Lock()


def increment():
    global counter
    with lock:
        counter += 1
~~~

Часто вместо общего изменяемого состояния используют очередь: producer кладёт задания, workers забирают их и возвращают результаты. Это проще контролировать и тестировать.

Для async-кода используют asyncio.Lock и asyncio.Queue. Нельзя подменять их блокирующими примитивами без понимания последствий.

## 7. Как выбрать подход

| Ситуация | Подход |
|---|---|
| Десятки синхронных HTTP-вызовов | ThreadPoolExecutor |
| Тысячи асинхронных соединений | asyncio |
| Чистый Python CPU-bound-код | ProcessPoolExecutor |
| NumPy, PyTorch, CUDA | Сначала векторизация и benchmark |
| Большие объекты между workers | Осторожно с multiprocessing и pickle |
| Нужно разделить отказ компонентов | Отдельные процессы или очереди |

Не следует выбирать asyncio только потому, что он «современнее». Если библиотека синхронная, небольшой ThreadPoolExecutor может быть проще и надёжнее.

## 8. Практический pipeline для ML-сервиса

Для обработки документов можно сочетать разные модели выполнения:

1. asyncio получает документы из внешнего API.
2. Потоки вызывают синхронный OCR-клиент.
3. Процессы выполняют CPU-тяжёлую обработку изображений.
4. asyncio сохраняет результаты в асинхронную базу.
5. Очередь отправляет неуверенные документы на ручную проверку.

На каждом переходе нужно ограничивать размер очереди и уметь повторить или безопасно пропустить неудачную задачу.

## 9. Типичные ошибки

- Использовать потоки для тяжёлых Python-циклов и ожидать ускорения.
- Запустить блокирующую функцию внутри event loop.
- Передать огромный объект каждому процессу и потратить всё время на pickle.
- Создать неограниченное число задач и получить rate limit.
- Изменять общую память без Lock.
- Повторить необратимый API-вызов без idempotency key.
- Считать, что параллелизм всегда уменьшает общее время: узкое место может быть в базе, сети или внешнем API.

## Вопросы для собеседования

> [!question] Чем конкурентность отличается от параллелизма?
> Конкурентность позволяет задачам продвигаться вперемешку. Параллелизм означает одновременное выполнение на разных ядрах или устройствах.

> [!question] Почему потоки полезны при наличии GIL?
> Пока один поток ждёт I/O, другой может работать. Кроме того, NumPy и некоторые C-расширения выполняют тяжёлую часть вне Python-байткода.

> [!question] Почему asyncio не ускоряет CPU-bound-код?
> Event loop переключается только в точках await. Длинный синхронный расчёт блокирует весь цикл.

> [!question] Когда выбрать процесс вместо потока?
> Когда нужно параллельно выполнять чистый Python CPU-код или изолировать память и ошибки компонента.
