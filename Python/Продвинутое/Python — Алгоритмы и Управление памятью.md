# Python — Алгоритмы и Управление памятью

> [!abstract] Суть
> Эффективность программы в Python зависит от алгоритма, количества создаваемых объектов, глубины вызовов и характера входных данных. На интервью важно понимать общую модель памяти, стоимость рекурсии и сложность операций, а не пытаться угадать конкретное расположение каждого объекта в CPython.

> [!tip] Быстрое повторение
> - Все обычные Python-объекты живут в управляемой куче; стек вызовов — полезная концептуальная модель кадров выполнения, но детали зависят от реализации.
> - Вызов функции создаёт новый frame, а глубокая рекурсия может привести к RecursionError.
> - sorted и list.sort используют стабильный адаптивный Timsort.
> - Timsort в лучшем случае близок к O(n) на почти отсортированных данных, в общем случае O(n log n).
> - Для поиска минимума или максимума не нужно сортировать весь массив: часто достаточно одного прохода O(n).

## Простыми словами

*   **Стек вызовов (Stack)** — удобная модель последовательности активных вызовов функций. Каждый вызов получает frame с локальными именами и точкой возврата. В CPython сами объекты и frame могут находиться в управляемой куче, поэтому не стоит буквально утверждать, что все значения лежат в стеке.
*   **Куча (Heap)** — область, где CPython размещает объекты: списки, словари, экземпляры классов и числа. Переменная хранит ссылку на объект, а не копию всего объекта.
*   **Сортировка**: Представьте, что вам нужно расставить книги по алфавиту. **Quicksort** — это стратегия «разделяй и властвуй» (выбираем книгу-ориентир и раскидываем остальные влево-вправо). **Timsort** (стандарт в Python) — это умный библиотекарь, который ищет уже упорядоченные цепочки книг и эффективно их объединяет.

## Ответ

**Формальные определения и устройство**

1.  **Стек (Stack)**
    *   **Назначение**: Управление потоком выполнения и локальными переменными.
    *   **Механика**: Работает по принципу Last-In-First-Out. При вызове функции создается «кадр стека» (stack frame).
    *   **Плюсы**: помогает управлять вложенностью вызовов и быстро возвращаться из функций.
    *   **Минусы**: слишком глубокая рекурсия приводит к RecursionError; увеличивать лимит без понимания нагрузки опасно.

2.  **Куча (Heap)**
    *   **Назначение**: Динамическое выделение памяти для всех объектов (списков, словарей, экземпляров классов).
    *   **Механика**: Объекты живут в куче до тех пор, пока на них есть ссылки. Памятью управляет сборщик мусора (GC).
    *   **Плюсы**: Гибкость, большой объем.

3.  **Алгоритмы сортировки**
    *   **Quicksort (Быстрая сортировка)**:
        *   *Алгоритм*: Выбор опорного элемента (pivot) -> разделение на подмассивы (< pivot и > pivot) -> рекурсия.
        *   *Сложность*: Средняя $O(n \log n)$, худшая $O(n^2)$.
    *   **Timsort (Стандартный sorted в Python)**:
        *   *Алгоритм*: Гибрид сортировки вставками (Insertion Sort) и сортировки слиянием (Merge Sort). Ищет в данных «прогоны» (уже отсортированные последовательности).
        *   *Сложность*: Стабильно $O(n \log n)$. В лучшем случае (почти отсортированные данные) — $O(n)$.

**Сравнение сложности сортировок**

| Алгоритм | Лучший случай | Средний | Худший | Память |
| :--- | :--- | :--- | :--- | :--- |
| **Quicksort** | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ | $O(\log n)$ |
| **Timsort** | $O(n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n)$ |

## Как оценивать алгоритм на интервью

Отвечая про алгоритм, называйте не только его название, но и:

1. размер входа;
2. сколько раз каждый элемент обрабатывается;
3. дополнительную память;
4. поведение на пустом и уже отсортированном вводе;
5. можно ли остановиться раньше;
6. сохраняется ли порядок равных элементов.

Например, чтобы найти максимальное число, не нужно сортировать массив:

~~~python
def find_max(values):
    if not values:
        raise ValueError("empty input")

    result = values[0]
    for value in values[1:]:
        result = max(result, value)
    return result
~~~

Время такого решения O(n), дополнительная память O(1). Полная сортировка дала бы O(n log n) и была бы лишней.

## Рекурсия и кадры вызовов

При каждом вызове функции создаётся новый frame с локальными именами и местом возврата. В рекурсивной функции такие кадры накапливаются до базового случая:

~~~python
def factorial(n):
    if n < 0:
        raise ValueError("n must be non-negative")
    if n == 0:
        return 1
    return n * factorial(n - 1)
~~~

Сложность factorial по времени O(n), а по глубине стека O(n). В Python глубокая рекурсия обычно хуже цикла: есть ограничение глубины и нет оптимизации хвостовой рекурсии.

## Стабильность сортировки и ключ

Стабильная сортировка сохраняет относительный порядок элементов с одинаковым ключом. Это позволяет сортировать сначала по вторичному признаку, а затем по основному или использовать несколько полей в одном ключе.

~~~python
users = [
    {"name": "Ann", "score": 10},
    {"name": "Bob", "score": 10},
    {"name": "Eva", "score": 8},
]

users.sort(key=lambda user: user["score"], reverse=True)
~~~

Ann останется перед Bob, потому что их значения score равны. Это полезно в аналитических пайплайнах и ранжировании, где нельзя случайно менять порядок равных объектов.

## Типичные ошибки

*   **RecursionError**: Попытка написать глубокую рекурсию без учета размера Стека. По умолчанию в Python лимит — 1000 вызовов.
*   **Ожидание O(n log n) от Quicksort на плохих данных**: Если неудачно выбрать опорный элемент на уже отсортированном массиве, Quicksort деградирует до $O(n^2)$. Timsort от этого защищен.

## Каверзные вопросы

> [!question] В чем главная «полезность» Кучи?
> Она позволяет хранить объекты, размер которых заранее неизвестен или может меняться (динамические структуры), и передавать их между функциями без копирования данных (передаем только короткую ссылку из Стека).

> [!question] Почему Python использует Timsort, а не Quicksort?
> Потому что в реальных данных часто встречаются уже частично упорядоченные последовательности. Timsort адаптируется к ним и работает значительно быстрее Quicksort. Кроме того, Timsort стабилен (сохраняет относительный порядок равных элементов), что важно для сортировки по нескольким полям.

## Вопросы для собеседования

> [!question] Все ли Python-объекты лежат в куче?
> В CPython обычные объекты размещаются в управляемой куче. Стек вызовов полезно использовать как модель вложенности функций, но не стоит буквально переносить на Python описание низкоуровневого стека из C.

> [!question] Почему sorted обычно O(n log n)?
> Для произвольных данных Timsort имеет такую верхнюю оценку. На почти отсортированных данных он может работать близко к O(n), используя готовые упорядоченные участки.

> [!question] Что означает стабильность сортировки?
> Равные по ключу элементы сохраняют исходный порядок. Это важно, когда у них есть вторичная бизнес-логика или предыдущая сортировка.

> [!question] Когда сортировка — плохое решение?
> Когда нужен только минимум, максимум, проверка существования или top-k. В таких случаях часто достаточно одного прохода или heapq.

> [!question] Почему рекурсия опасна в Python?
> Каждый вызов занимает frame, глубина ограничена, а хвостовая рекурсия не оптимизируется. Для линейных рекурсивных задач обычно выбирают цикл.
