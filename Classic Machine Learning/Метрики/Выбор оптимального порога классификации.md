# Выбор оптимального порога классификации

> [!abstract] Суть
> Переход от вероятностей к классам требует выбора порога (threshold). Оптимальный порог зависит от целей бизнеса: стоимости ошибок (FP vs FN) или целевых уровней охвата (Recall).

## Ответ

Выбор порога $0.5$ по умолчанию оправдан только в идеально сбалансированных задачах с равной стоимостью ошибок. На практике используют три группы методов:

### Группа 1: Cost-Sensitive (Когда известны цены ошибок)
Мы выбираем порог, который минимизирует ожидаемые потери бизнеса.
- **Формула:** Теоретически оптимальный порог $P^* = \frac{C_{FP}}{C_{FP} + C_{FN}}$.
- **Пример:** Если пропустить мошенника ($FN$) стоит 100$, а ложно обвинить честного ($FP$) стоит 10$, то $P^* = 10 / (10 + 100) \approx 0.09$. Мы должны снизить порог, чтобы ловить больше подозреваемых.

### Группа 2: Performance Curves (Когда есть цели по метрикам)
- **Recall Target:** «Нам нужно ловить 95% больных». Ищем на PR-кривой точку с $Recall=0.95$ и смотрим соответствующий порог.
- **FPR Constraint:** «Мы не можем беспокоить службу поддержки чаще, чем в 5% случаев». Ищем на ROC-кривой точку с $FPR=0.05$.
- **Индекс Юдена (Youden's J):** $J = TPR - FPR$. Максимизация этого индекса дает порог с наилучшим балансом между захватом позитивов и избеганием ложных тревог.

### Группа 3: Data-Driven (Анализ распределения)
- **Метод «локтя»:** Строим гистограмму предсказанных вероятностей. Оптимальный порог обычно находится в «седловине» между двумя пиками распределений классов.

## Формула / Схема

**Поиск порога через Youden's J index:**
$$J(t) = \text{Sensitivity}(t) + \text{Specificity}(t) - 1 = \text{TPR}(t) - \text{FPR}(t)$$

## Короткий пример

**Поиск порога по сетке на Python:**
```python
thresholds = np.linspace(0, 1, 100)
costs = [compute_cost(y_true, y_probs >= t, c_fp, c_fn) for t in thresholds]
optimal_t = thresholds[np.argmin(costs)]
```

## Типичные ошибки

- **Порог 0.5 при дисбалансе:** Использовать стандартный порог, когда один класс встречается в 100 раз реже другого.
- **Выбор порога по AUC:** Помнить, что AUC — это агрегатная метрика по всем порогам. Конкретный рабочий порог выбирается *на* кривой, а не *по* её площади.

## Каверзные вопросы

> [!question] Что делать, если стоимость FP и FN меняется со временем?
> В этом случае модель должна выдавать вероятности, а порог должен быть динамическим параметром, который бизнес-логика подставляет «на лету» перед принятием решения.
